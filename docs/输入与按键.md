# 输入与按键（输入事件系统手册）

引擎把「玩家按了什么」和「引擎要做什么」分成两层：设备产生的事件（键盘 / 鼠标 / 滚轮 / 手柄）先被翻译成**动作**（action），动作再交给**处理器**（handler）执行。作者只需关心动作清单与推荐映射；玩家可以逐动作改绑定，改动只存在本机浏览器里。

相关文件：

| 文件 | 职责 |
|---|---|
| `style/input.js` | 动作表、绑定解析、事件分发、快捷轮盘、按键捕获、截图 |
| `theme.json` 的 `input` | 推荐映射方案（作者写的默认值） |
| `theme.json` 的 `pages.settings.sections` | 设置页渲染哪些项、顺序、文案 |
| `style/settings.js` | 设置项的**存在性与取值范围**（`SPECS`） |
| `style/pages/radial.css` | 轮盘的形态与半径（半径的唯一来源，`input.js` 呼出时读回去用） |

## 1. 事件 → 动作 → 处理器

### 1.1 三层职责

```
设备事件（keydown / pointerup / wheel / 手柄轮询）
      ↓  按「此刻生效的绑定表」匹配
动作（Advance / QuickSave / …，共 24 个）
      ↓  按 priority 从大到小派发
处理器（engine.js / script.js / 工程自定义 UI 注册）
```

`input.js` 不认识剧情，也不内置任何一套字面默认绑定。它只知道动作名；「Advance 是下一句」由 `script.js` 注册，默认绑定由 `theme.json` 提供。

### 1.2 派发顺序与「消费」

一次事件可能同时命中多个动作。例如按回车既命中 `Confirm`（priority 100）又命中 `Advance`（priority 40）：

1. 命中的动作按 `priority` 降序排列，同优先级按动作表顺序。
2. 依次派发，**第一个返回 `true` 的处理器消费掉该事件**，后面的不再执行。
3. 动作不可用（`registerAvailability` 返回假值）时直接跳过，不算命中。

由此得到一条硬约束：**高优先级动作的处理器必须在自己不适用时返回 `false`**，否则会吞掉本该落到低优先级动作的事件。`Confirm` 的判据是「当前确实有一个带确认按钮、且处于 `is-active` 的浮层」，而不是「DOM 里存在这样一个按钮」——退出确认框是常驻页面的，只靠 `.is-active` 隐藏。

### 1.3 三条边界

| 边界 | 行为 |
|---|---|
| 只翻译、不吞 | 除「按键捕获」与「轮盘打开」两种独占态外，不改事件默认行为；只有确实命中动作时才 `preventDefault` |
| Esc 不拦截 | `Esc` 的 `keydown` 不 `preventDefault`，否则浏览器收不到「退出全屏」的默认处理 |
| 不抢页面 UI | 落在交互目标上的点击不翻译成动作；表单控件内的按键还给控件 |

## 2. 动作表

`priority` 越大越先派发。`按住` 表示事件在 `keydown` 触发、`keyup` 结束（长按不会连发）。`仅滚轮` 表示该动作只接受滚轮设备的绑定，并受「滚轮回看」设置项开关控制。

| 动作 id | 界面文案 | 短名 | priority | 按住 | 仅滚轮 | 默认方案绑定 |
|---|---|---|---|---|---|---|
| `Advance` | 下一句 / 推进剧情 | 下一句 | 40 | | | `mouse:left`、`key:enter`、`key:space`、`pad:a` |
| `Rollback` | 上一句 / 回到历史位置 | 上一句 | 60 | | | `key:pageup`、`pad:lb` |
| `ScrollBack` | 回看（向上滚动） | 回看 | 70 | | ✓ | `wheel:up` |
| `ScrollForward` | 回到当前（向下滚动） | 回到当前 | 70 | | ✓ | `wheel:down` |
| `History` | 打开历史文本 | 历史 | 55 | | | `mouse:middle`、`pad:left` |
| `Auto` | 自动播放 | 自动 | 55 | | | `key:a`、`pad:y`、`pad:up` |
| `SkipRead` | 跳过已读文本 | 跳已读 | 55 | | | `key:tab` |
| `SkipAll` | 跳过全部文本 | 跳全部 | 55 | | | `key:shift+tab` |
| `FastForward` | 快进（按住） | 快进 | 55 | ✓ | | `key:control` |
| `HideUI` | 隐藏 / 显示 UI | 隐藏UI | 50 | | | `key:h`、`pad:b` |
| `OpenMenu` | 打开游戏菜单 | 菜单 | 50 | | | `mouse:right`、`pad:x`、`key:escape` |
| `OpenSave` | 打开保存界面 | 保存 | 50 | | | 无 |
| `OpenLoad` | 打开读档界面 | 读取 | 50 | | | 无 |
| `QuickSave` | 快速保存 | 快存 | 50 | | | `key:f5`、`pad:right` |
| `QuickLoad` | 快速读档 | 快读 | 50 | | | `key:f9`、`pad:down` |
| `OpenSettings` | 打开设置 | 设置 | 50 | | | 无 |
| `OpenGallery` | 打开鉴赏 / 画廊 | 画廊 | 50 | | | 无 |
| `OpenLog` | 打开文本 Log | Log | 54 | | | 无 |
| `Screenshot` | 截图 | 截图 | 45 | | | 无 |
| `Fullscreen` | 全屏切换 | 全屏 | 45 | | | 无 |
| `Cancel` | 返回 / 取消 | 取消 | 100 | | | `key:escape`、`pad:b` |
| `Confirm` | 确认当前 UI 项 | 确认 | 100 | | | `key:enter`、`key:space`、`pad:a` |
| `MenuUp` | 列表上移 | 上移 | 95 | | | `key:arrowup`、`pad:up` |
| `MenuDown` | 列表下移 | 下移 | 95 | | | `key:arrowdown`、`pad:down` |

「无」表示标准方案不给该动作任何绑定（功能仍可用：玩家可以在设置页自行绑定，工程也可以直接调 `fire()`）。表中的「默认方案绑定」列取 `input.default` 指定的方案（模板里是 `primary`）。

手柄布局（两套推荐方案一致，2026-10-01 重排）：A = 推进 / 确认；B = 隐藏 UI —— **同时也绑了 `Cancel`**，靠优先级分层：有东西可退（浮层、弹窗、菜单页）时是「返回」，在舞台上是「隐藏 UI」；X = 菜单；Y = 自动；LB = 上一句；十字键四向 = 快捷轮盘四格的默认动作（上 = 自动、右 = 快存、下 = 快读、左 = 历史）。十字键上下在有选项列表时先归列表导航（`MenuUp` / `MenuDown` 优先级更高，且不适用时返回假值放行）。引擎内置的行为映射：

| 动作 | 引擎默认行为 | 实现位置 |
|---|---|---|
| `Advance` / `Rollback` / `ScrollBack` / `ScrollForward` / `Auto` / `SkipRead` / `SkipAll` / `FastForward` | 剧情播放控制 | `script.js` |
| `Confirm` / `MenuUp` / `MenuDown` | 选项导航与确认 | `script.js` |
| `Cancel` / `OpenMenu` / `OpenSave` / `OpenLoad` / `OpenSettings` / `OpenGallery` / `History` / `OpenLog` / `QuickSave` / `QuickLoad` / `HideUI` | 页面与浮层 | `engine.js` |
| `Screenshot` / `Fullscreen` | 引擎能力（可被更高优先级的处理器覆盖） | `input.js` |

### 2.1 覆盖动作文案：`input.actionLabels`

```json
{
  "input": {
    "actionLabels": {
      "Advance": { "label": "继续阅读", "short": "继续" },
      "QuickSave": "即时存档"
    }
  }
}
```

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `input.actionLabels.<动作id>` | object 或 string | 否 | 写成对象时可用 `label` 与 `short` 分别覆盖长名与短名；写成字符串等于只覆盖 `label` | 引擎内置中文 |

`short` 用于轮盘格子这类窄容器。设置页的动作下拉框使用长名。

## 3. 绑定字符串语法

绑定是字符串，既由作者写在 `theme.json`，也用作玩家自定义绑定的存储格式。

### 3.1 语法总表

| 设备 | 写法 | 可用取值 |
|---|---|---|
| 键盘 | `key:<键名>` | `KeyboardEvent.key` 归一化后的写法，见 3.2 |
| 键盘（带修饰键） | `key:<修饰键>+<键名>` | 修饰键可组合，顺序固定 `ctrl`、`alt`、`shift`、`meta`，如 `key:ctrl+shift+a` |
| 鼠标 | `mouse:<按键>` | `left`、`middle`、`right`、`x1`、`x2` |
| 滚轮 | `wheel:<方向>` | `up`、`down`、`left`、`right` |
| 手柄 | `pad:<别名>` | `a`、`b`、`x`、`y`、`lb`、`rb`、`lt`、`rt`、`back`、`start`、`l3`、`r3`、`up`、`down`、`left`、`right`，或数字下标 `pad:0`…`pad:31` |

非法字符串（未知设备、未知修饰键、空键名、手柄下标越界）在解析时被丢弃，不会进入生效绑定表。作者写错只会让该条绑定失效，不会报错中断。

### 3.2 键盘键名归一化规则

| `KeyboardEvent.key` | 归一化结果 | 说明 |
|---|---|---|
| `" "` | `space` | 空格键。判定在 `trim()` 之前，`" "` 不会被当成空串 |
| `"Esc"` | `escape` | 旧式写法 |
| 单个字符（`"A"`、`"1"`、`","`） | 小写（`a`、`1`、`,`） | 因此大写字母用修饰键表达：`key:shift+a` |
| 其它 | 全小写（`"ArrowUp"` → `arrowup`，`"PageUp"` → `pageup`，`"F5"` → `f5`） | |

常用写法：`key:enter`、`key:space`、`key:escape`、`key:tab`、`key:arrowup`、`key:pageup`、`key:f5`、`key:h`、`key:control`。

### 3.3 一个动作绑多个设备

```json
{
  "Advance": ["mouse:left", "key:enter", "key:space", "pad:a"]
}
```

数组元素之间是「或」关系：命中任意一条即视为该动作被触发。

## 4. 推荐方案：`theme.json` 的 `input`

作者写的默认映射被当作**推荐**，不是强绑。玩家在设置页可以逐动作改选推荐方案或自定义按键。

### 4.1 字段表

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `input.default` | string | 否 | 玩家没有做过选择时跟随的方案 id；该 id 不存在时退化为第一个方案 | 第一个 `presets` 的 `id`；`presets` 为空时为空串 |
| `input.presets` | array | 否 | 推荐方案列表。不写等于不提供任何推荐映射 | `[]` |
| `input.presets[].id` | string | 是 | 方案 id，玩家选择以它为键存储 | — |
| `input.presets[].label` | string | 否 | 设置页下拉框里显示的名字。**写短一些**：下拉框是原生控件、宽度有限，名字过长在收起状态下会被截断（展开时按最长选项撑开，能看到全名） | 等于 `id` |
| `input.presets[].bindings` | object | 否 | 动作 id → 绑定字符串数组。未列出的动作在该方案下为「零绑定」 | `{}` |

可以写多套方案。典型用法是一套主方案加一套备用方案（例如给「不用鼠标点击推进」的玩家）。

### 4.3 玩家改动与存储

| 项目 | 内容 |
|---|---|
| 存储位置 | `localStorage`，键为 `aliceadv.bindings.<游戏名>` |
| 命名空间 | 由 `AliceADVSettings.storageKeyFor()` 统一生成，`<游戏名>` 取 `info.json` 的 `name` 并替换掉会破坏键名的字符；同名不同作品互不干扰 |
| 取值形状 | `{ "<动作id>": { "preset": "<方案id>" } }` 或 `{ "<动作id>": { "custom": ["key:j"] } }` |
| 未记录的动作 | 跟随 `input.default` |
| 清空某动作 | 删除该键，回到「跟随默认方案」 |
| 与设置项的关系 | 与 `aliceadv.settings.<游戏名>` 分开存放 |

玩家选择推荐方案时只存方案 id。作者日后改了该方案的绑定，跟随它的玩家会自动跟着变；选了「自定义」的玩家不受影响。

模板里的两套方案：`primary`（方案名「标准」）适合键鼠 + 手柄，`nomouse`（方案名「备用」）去掉了鼠标点击推进、并给菜单补了一个键盘键位，适合不希望误触鼠标推进的玩家。方案名写短是因为设置页的下拉框是原生控件、收起时按控件宽度截断（详见 7.4）。

## 5. 滚轮回看

### 5.1 行为

滚轮参与剧情的方式与「上一句 / 下一句」不同：它只在**已读过的内容**之间移动。

| 操作 | 行为 |
|---|---|
| 向上滚 | 位置回退到前一句已读内容。位置回退**不丢弃**历史，快照数组长度不变 |
| 向下滚 | 位置前进，回到「当前所在句」 |
| 到达当前位置后继续向下滚 | 不动作，**不会**推进到下一句 |

「向下滚不推进」是实现上的硬约束：位置（`state.viewIdx`）与历史（`state.snaps`）是两份数据，只有真正的 `Advance` 才会截断「当前位置之后」的快照。

### 5.2 设置项

| 设置键 | 类型 | 说明 | 默认值 |
|---|---|---|---|
| `wheelReview` | bool | 关闭后，滚轮设备的回看绑定全部失效；键盘上与 `ScrollBack` / `ScrollForward` 相同的绑定不受影响 | `true` |

### 5.3 限制

- 只有标了「仅滚轮」的动作会受 `wheelReview` 影响。
- 指针落在可滚动区域（历史列表、关于页正文等）时，滚轮事件交还给浏览器，不翻译成动作。
- 轮盘打开时滚轮被轮盘独占。

## 6. 快捷轮盘

轮盘是一个挂在 `body` 根部的 `div`（`#aliceadv-radial`），默认隐藏。

### 6.1 交互定义

| 操作 | 结果 |
|---|---|
| 在任意位置按住超过设定时长 | 以按住点为圆心呼出轮盘 |
| 继续按住、拖进某个方向的 1/4 圆环 | 该环高亮 |
| 在环上松手 | 执行该方向配置的动作 |
| 原地松手，或停在中心圆 / 中心与环之间的空隙里松手 | 无动作（取消） |

具体约束：

| 项目 | 值 | 说明 |
|---|---|---|
| 尺寸 | 外直径 = 画面高度的 30% | `radial.css` 的 `--radial-d: 30vh`。其余半径全部由它按比例派生，换窗口 / 换分辨率整圈等比缩放 |
| 判定半径 | 圆环的内半径（= 外半径 × 0.55） | 与圆心距离小于该值时视为「中心」。`input.js` 量元素得到，与眼睛看到的环内缘是同一个数 |
| 呼出前的抖动容忍 | 10 屏幕 px | 超过则视为拖动，不呼出轮盘 |
| 屏幕边缘内移 | 外半径 + 24 屏幕 px | 按住点距屏幕边缘小于该值时圆心向内移动，保证整圈（连同它那层投影）都在屏幕内；**方向判定以圆心为基准**，不是手指原位置。24 = 投影的偏移 8 + 模糊 22，改 `radial.css` 的 `drop-shadow` 要一起改 `input.js` 的 `RADIAL_MARGIN_SLACK` |
| 触发时长下限 | 120 ms | 即使设置项写得更小也按 120 ms 生效 |
| 长按那一次松手 | 不翻译成动作 | 避免「长按取消」同时触发一次推进 |

呼出轮盘被跳过的情形：按在表单控件上、按在交互目标上（按钮、滑块、列表、浮层等）、轮盘功能被关闭、处于按键捕获状态。

### 6.1.1 几何

四个方向不是四个圆点，而是**四个 1/4 圆环**，拼成一个中间被挖空的整环。整圈只钉一个尺寸不变量：**外直径 = 画面高度的 30%**（`--radial-d: 30vh`），其余全部由它按比例派生。

| 项目 | 做法 |
|---|---|
| 为什么是 1/4 圆环 | 每个方向是一个 `2×外半径` 见方的元素，`border-radius: 50%` 使它成圆，只给一条边涂色。圆角 50% 的方框，四条边框正好各占 90° |
| 与方向判定对齐 | 相邻两条边沿对角线（45°）交接，与 `input.js` 的 `|dx| >= |dy|` 判定分界重合 |
| 环的厚度 | `border` 的宽度 = `--radial-r-out` − `--radial-r-in` = 外半径 × 0.45。外边即外半径、内边即内半径，所以圆心附近是空的 |
| 相邻两环之间的缝 | 每个 1/4 环用 `conic-gradient` 当面罩，两端各切掉 `--radial-gap`（默认 `2deg`，角度不随尺寸变）；否则四块同色填充会连成一整圈，看不出是四个 |
| 环的内缘 / 外缘细线 | 内外缘各描一圈 1px 细线（`1px` 是刻意不缩放的），且按同样的缝断开（`repeating-conic-gradient`，周期 90°）。描边不断开的话，一个完整的圆箍会把四个同色环重新读成一个整环。颜色取调色板的 `--radial-line`（莫兰迪雾霾蓝 `#93A8BB`，不跟随主题），**外深内浅**由两圈各自的 `opacity`（`0.75` / `0.35`）实现 |
| 中心「取消」圆 | 直径 `--radial-center-d` = 外半径 × 0.6，与环的内缘之间留「外半径 × 0.25」的净空隙 |
| 标签字号 | `clamp(11px, 外直径 × 0.05, 22px)`；中心略大（外直径 × 0.058）。随轮盘缩放，下限保证小窗口仍可读 |

半径**只在 `radial.css` 里定义一份**（`--radial-d` → `--radial-r-out` → `--radial-r-in`），`input.js` 呼出时**量元素**把它们取回来（`.radial` 的宽 = 2×外半径、内缘细线的宽 = 2×内半径）当判定半径与边缘内移用。注意不要改成 `parseFloat(getComputedStyle(...).getPropertyValue("--radial-r-out"))`：自定义属性的计算值是 `calc(var(--radial-d) / 2)` 这样**未化简**的表达式，`parseFloat` 只会拿到 `NaN` 并静默退回兜底值，判定半径与视觉半径又分家（「看着够到圆环了却没选中」就是这么来的）。也不要再在 JS 里另写一个半径。

### 6.1.2 视觉语言（关于页的版式 + 轮盘自己的莫兰迪调色板）

轮盘的外观照搬关于页那张纸的三要素（`.about-panel` + `.about-meta`），两者放在一起像一家人；但**颜色不跟随主题 `accent`**——工程常是单色主题（本工程 `colors.accent` = `#000000`），跟着走时轮盘的选中格 / 细线 / 文字全是黑白灰，观感「死板肃杀」（2026-10-01 用户反馈）。轮盘是游戏感的小覆盖层，用自己的一套低饱和度（莫兰迪）色，全部是**字面值**写在 `.radial` 的取色段里：

| 要素 | 关于页 | 轮盘 |
|---|---|---|
| 面 | 半透明白纸（`gameMenu.panelColor`，默认 `rgba(255,255,255,0.85)`） | `--radial-face`，**与之同值**；中心格更实一点（`--radial-face-center`，`0.94`） |
| 线 | 版本胶囊的 1px 强调色描边 | 外缘 / 内缘各一圈 1px 细线，颜色取 `--radial-line`（莫兰迪雾霾蓝 `#93A8BB`），**外深内浅**由两圈各自的 `opacity`（`0.75` / `0.35`）实现 |
| 影 | `0 12px 32px rgba(0,0,0,0.18)` | 整圈共用**一层** `drop-shadow(0 8px 22px rgba(31,41,51,0.16))`（`drop-shadow` 跟着 alpha 轮廓走，挖空的圆心与环缝不会被涂黑；中心圆不带自己的投影，两层叠起来像贴上去的贴纸） |

| 状态 | 表现 |
|---|---|
| 未选中 | 半透明白纸 + 深灰蓝文字（`--radial-ink`，`#5D6B77`，比纯黑柔），安静不抢戏 |
| 选中（`is-hot`） | 那一格的纸**染成灰玫瑰**（`--radial-face-hot`，`rgba(226,200,198,0.97)`），文字换成**玫瑰棕**（`--radial-ink-hot`，`#96625E`）并**加粗**（`500` → `700`），另加一点同色柔光（`filter: drop-shadow`，不想要可单独删掉） |
| 不可用（`is-disabled`） | 整体压到 45% **并且**文字转 `--color-insensitive`。不能只降不透明度：面本来就是半透明白，再压一档会彻底看不见。指向它时不再染色（本来就不能用），只把纸压到最实 |

**选中态刻意不做「整块填成饱和色」**，两个理由：

1. 本引擎表达「选中 / 当前」从来只用变色（+ 加粗）——`.paper-btn.is-selected`、`.paper-btn.is-current`、`.page-jumper .pj-num.is-current`、`.checkbox.is-checked` 都是如此；全引擎唯一的实色是 `slider` 那条 6px 轨道。轮盘是这套界面的一部分，不该自己发明一种「选中」的写法。
2. 实色块压在暗场景图像（如 `images/bg/roof.png` 下半部的屋顶）上轮廓直接消失，只剩那行文字在飘，反而看不清指向的是哪一格。

想换回实色块：把 `--radial-face-hot` 改成 `var(--color-accent)` 一处，并把 `--radial-ink-hot` 同时改浅（否则深底深字读不出来）。

改动配色只需要动 `.radial` 取色段那几行字面值（`--radial-face` / `--radial-face-center` / `--radial-face-hot` / `--radial-ink` / `--radial-ink-hot` / `--radial-line` / `--radial-rose-deep`），再按需调两圈细线的 `opacity`（写在 `.radial__edge--out` / `.radial__edge--in` 里）。`--sector` 是它们的调度者：四个方向格用它当 `border-color`、中心格用它当 `background-color`，所以选中态才能一套变量管到底。想让轮盘跟随主题色，把其中几个换成 `var(--color-accent)` 一系即可。

⚠️ **不能用不透明的纸色当环体**：舞台底色本身就是奶油纸色（`--color-paper` = `#FAF8F0`），环再用纸色就直接隐形，屏幕上只剩一圈细线在飘。「半透明白」在任何底色上都能读出来，这也是关于页那张纸同样选择半透明的原因。

⚠️ **`color-mix` 的兜底只能写在「真实属性」上**。「先写一行 rgba 兜底、再写一行 `color-mix`」这种写法，只在 `border-color` / `background-color` / `filter` 这类真实属性上成立：不支持 `color-mix` 的浏览器会在**解析阶段**把后一行判为非法并整条丢弃，前一行于是生效。写在**自定义属性**上则不成立——`--x: color-mix(...)` 永远是一段合法 token（自定义属性不校验值），后一行必定胜出；真不支持时它要到 `var()` 展开处才变成非法值，那时整条声明按「计算值非法」处理（回退到 `initial`），前一行**兜不住**，那行就成了死代码。`radial.css` 自 2026-10-01 改用**字面调色板**后整份文件不再出现 `color-mix`；这条规则对其余页面（关于页 hover、settings.css 等）仍然适用。

⚠️ **`var()` 的兜底字面量必须等于模板 `theme.json` 的默认值**。写 `var(--主题变量, 字面兜底)` 时，兜底字面量必须与模板 `theme.json` 里该键的默认值一致。写错不会报错、也不会在正常主题下显形（主题变量由构建期**恒定写入**，兜底分支根本不触发），只会在极端情况下悄悄偏一点色 —— `radial.css` 就曾把 `#3B59`**`98`** 写成 `#3B59`**`88`**（后两位颠倒），长期没被发现。`radial.css` 现在只读一个主题变量（置灰文字的 `var(--color-insensitive, #888888)`），这条规则对其余页面的 CSS 同样适用；改模板默认色时把所有兜底一起改（本仓库没有断言守这层对应关系）。

## 7. 设置页：分区与顺序

设置页渲染哪些项、以什么顺序、用什么文案，全部由 `theme.json` 的 `pages.settings.sections` 决定。改版面不需要动引擎代码。

### 7.1 `pages.settings.sections` 字段表

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sections` | array | 否 | 分区列表。为空或缺省时，引擎把 `SPECS` 中登记过的项按登记顺序铺成一页 |
| `sections[].title` | string | 否 | 分区标题 |
| `sections[].items` | array | 是 | 分区内的条目 |
| `items[].key` | string | 是 | 设置项键名，必须已在 `settings.js` 的 `SPECS` 中登记，否则该条被跳过并打印告警 |
| `items[].label` | string | 否 | 标签文案；`bool` 类型不显示标签 | 
| `items[].chipLabel` | string | 否 | `bool` 类型开关上显示的文案 | 
| `items[].hint` | string | 否 | 控件下方的说明文字 |
| `items[].full` | bool | 否 | 占满整行（用于说明较长的条目） |
| `items[].options` | array | 否 | `enum` 类型的选项文案，元素为 `{ "value": …, "label": … }`；不写则直接用取值 |
| `items[].type` | string | 否 | 写 `"keymap"` 时该条渲染为按键映射区块，此时不用 `key`，可用 `title` 与 `hint` |

### 7.2 控件形态由谁决定

| 关注点 | 唯一来源 |
|---|---|
| 该项是否存在、类型是什么、取值范围、默认值、锁定关系 | `style/settings.js` 的 `SPECS` |
| 该项是否显示、显示在哪个分区、第几个、用什么文案 | `theme.json` 的 `pages.settings.sections` |

设置页不会凭空造出 `SPECS` 里没有的项，也不会因为 `sections` 里没写而丢掉取值范围。被 `mutes` 锁定的项（如 `muteAll` 锁住三个音量项）由 `SPECS` 声明，页面只负责把它渲染出来。

### 7.3 示例

```json
{
  "pages": {
    "settings": {
      "title": "设置",
      "sections": [
        {
          "title": "文本与播放",
          "items": [
            { "key": "textSpeed", "label": "文字显示速度" },
            { "key": "skipUnseen", "label": "跳过未读文本", "chipLabel": "Unseen Text" }
          ]
        },
        {
          "title": "操作",
          "items": [
            { "key": "wheelReview", "label": "滚轮回看", "chipLabel": "滚轮回看" },
            { "key": "radialEnabled", "label": "快捷轮盘", "chipLabel": "快捷轮盘" },
            { "key": "radialHoldMs", "label": "轮盘触发时长", "full": true }
          ]
        },
        {
          "title": "轮盘方向",
          "items": [
            { "key": "radialUp", "label": "上" },
            { "key": "radialCenter", "label": "中心（松手＝取消）", "full": true }
          ]
        },
        {
          "title": "按键映射",
          "items": [
            {
              "type": "keymap",
              "title": "按键 / 鼠标 / 滚轮 / 手柄",
              "hint": "每个动作都可以选一套作者提供的推荐方案，或选「自定义」后按下你要的按键。改动只保存在本机浏览器里。"
            }
          ]
        }
      ]
    }
  }
}
```

### 7.4 按键映射区块

`type: "keymap"` 渲染为一张表，每个动作一行，包含：

| 列 | 内容 |
|---|---|
| 动作名 | 取自动作表的长名 |
| 下拉框 | 全部推荐方案（值为 `p:<方案id>`）+「自定义」（值为 `custom`）。收起时显示「方案名：该方案下这个动作的键位」，展开时能看全每个方案会给到什么键 |
| 当前键位 | 该动作此刻生效的绑定，以中文标签显示，如「回车」「鼠标左键」「手柄 A」 |
| 操作 | 已选自定义时可增删按键；可一键清空回「跟随推荐方案」 |
| 冲突提示 | 该动作的绑定与其它动作共用时给出提示 |

玩家选「自定义」后按下按键即完成捕获。捕获态的取值规则：

| 输入 | 结果 |
|---|---|
| 普通键 | 绑定为该键（含同时按下的修饰键） |
| `Esc` | 取消捕获，不修改绑定 |
| 单独按下 `Shift` / `Ctrl` / `Alt` / `Meta` | 忽略，等真正的按键。否则想绑 `Shift+A` 会先被 `Shift` 占掉 |
| 鼠标中键 / 右键 / 侧键 | 绑定为该键。左键在捕获态里是「点按钮」本身，不参与捕获 |
| 滚轮方向 | 绑定为该方向 |

捕获期间页面进入独占态（`body.is-capturing-binding`），除上表输入外不翻译任何事件。

### 7.5 设置项规格表

| 类型 | 渲染形态 | 可用附加字段 |
|---|---|---|
| `bool` | 开关 | `mutes`：打开后锁定的其它设置项 |
| `unit` | 滑块，显示为百分比 | |
| `int` | 滑块，显示为「数值 + 单位」，按 `step` 取整 | `min`、`max`、`step`、`unit` |
| `enum` | 一组互斥的分段按钮 | `options`：合法取值数组 |
| `action` | 动作下拉框，含「无」 | |

## 8. 运行时 API：`AliceADVInput`

工程可以通过 `window.AliceADVInput` 接入自己的 UI。动作的可用性判据只有一处，因此按键触发与 `fire()` 的行为完全一致。

### 8.1 处理器注册

| 方法 | 说明 |
|---|---|
| `register(action, fn, opts)` | 为动作注册处理器。`fn(ev)` 返回 `true` 表示消费该事件、不再传给后面的处理器；返回 `false` / `undefined` 表示不归自己管。`opts.priority` 越大越先派发（同动作内）。未知动作名会被忽略并打印告警 |
| `registerAll(map, opts)` | 批量注册，`map` 为「动作 id → 处理器」 |
| `registerAvailability(action, fn)` | 声明该动作「此刻能不能用」。假值时事件不会派发给它，轮盘对应格置灰。不注册即为始终可用 |

### 8.2 查询

| 方法 | 说明 |
|---|---|
| `actions()` | 全部动作，元素为 `{ id, label, short, hold, wheelOnly, priority }` |
| `actionLabel(action, short)` | 动作的显示文案（`short` 为真时取短名） |
| `presets()` | 全部推荐方案，元素为 `{ id, label, bindings }` |
| `defaultPreset()` | `input.default` 解析出的方案 id |
| `bindingsFor(action)` | 该动作此刻生效的绑定字符串数组 |
| `presetBindings(presetId, action)` | 指定方案下该动作的绑定 |
| `selection(action)` | 该动作此刻的来源，形如 `{ preset }`、`{ custom }` 或 `{ preset: <默认> }` |
| `conflicts(action)` | 与该动作共用绑定的其它动作 id 列表 |
| `parseBinding(str)` | 绑定字符串 → 结构对象；非法时返回 `null` |
| `formatBinding(b)` | 结构对象 → 规范化字符串 |
| `describeBinding(str)` / `describeBindings(list)` | 绑定 → 中文标签 |
| `onBindingsChange(fn)` | 订阅绑定变化（玩家改绑定或 `setSelection`）。返回取消订阅的函数 |

### 8.3 执行与修改

| 方法 | 说明 |
|---|---|
| `fire(action, ev)` | 直接执行动作，不经过设备匹配。用于工具栏按钮、自定义 UI。动作不可用时返回 `false` |
| `available(action)` | 该动作此刻是否可用 |
| `setSelection(action, sel)` | 修改玩家的绑定来源。`{ preset: "<方案id>" }` 跟随推荐方案；`{ custom: [...] }` 自定义；`null` 清空回默认。改动立即写入本地存储 |
| `refresh()` | 主题或推荐方案变化后重建生效绑定表 |

### 8.4 按键捕获

| 方法 | 说明 |
|---|---|
| `captureStart(cb, onCancel)` | 进入捕获态，下一个键 / 鼠标中右键 / 滚轮方向作为绑定字符串传给 `cb`；`Esc` 或环境中断（窗口失焦）时调用 `onCancel` 并恢复 |
| `captureCancel()` | 主动退出捕获态 |
| `isCapturing()` | 是否处于捕获态 |

### 8.5 截图与初始化

| 方法 | 说明 |
|---|---|
| `screenshot()` | 按舞台状态重绘一张 PNG 并触发下载，返回 Promise。它合成「背景 + 立绘 + 对话框」的定格，不是像素级拷贝，与字体渲染、滤镜、圆角存在差异。需要精确截图时注册一个优先级更高的 `Screenshot` 处理器覆盖 |
| `init()` | 绑定全局事件并注册引擎默认处理器。由 `index.html` 的启动流程调用，工程无需自行调用 |

## 9. 限制与注意事项

| 限制 | 说明 |
|---|---|
| 表单控件内的按键 | 焦点在 `input` / `textarea` / `select` / `contenteditable` 内时，按键还给控件，不翻译成动作；`Esc` 例外，仍按 `Cancel` 处理 |
| 交互目标上的点击 | 落在 `button`、`a`、`.toolbar`、`.choices`、`.popup`、`.notify`、`.slider`、`.seg`、`.slot`、`.keymap` 等元素上的点击不翻译成动作，交给页面自身的点击处理器 |
| 拖拽不算点击 | 按下与松手之间位移超过 8 屏幕 px 时不翻译成鼠标动作 |
| 预加载遮罩期间 | 资源兜底等待（`#wait-mask` 显示中）期间的推进被丢弃。这是 `script.js` 的守卫，不是输入系统的问题 |
| 背景转场期间 | 转场未落定时，第一次推进只结算转场，不推进一句；新图仍在解码时的推进被丢弃 |
| 高频事件 | 自动重复的 `keydown`（长按）只派发给「按住」类动作，避免按住回车连发推进 |
| 手柄 | 通过 `requestAnimationFrame` 轮询 `navigator.getGamepads()`，只在按下与松开的边沿派发；无手柄时不启动轮询。按钮下标范围 0 ~ 31 |

## 10. 速查表

| 目标 | 做法 |
|---|---|
| 改默认按键 | 改 `theme.json` 的 `input.presets[].bindings` |
| 提供两套可选映射 | 在 `input.presets` 里写两个方案，`input.default` 指定默认跟随哪一个 |
| 让某功能默认不绑键 | 在该方案的 `bindings` 里不写这个动作 |
| 改动作在界面上的名字 | 写 `input.actionLabels` |
| 调整设置页有哪些项、顺序 | 改 `pages.settings.sections` |
| 新增一个设置项 | 先在 `settings.js` 的 `SPECS` 登记，再在 `sections` 里引用 |
| 往设置页插按键映射表 | 在 `sections` 里加一条 `{ "type": "keymap" }` |
| 让滚轮不参与剧情 | 把设置项 `wheelReview` 的默认值改为 `false`，或让玩家在设置页关闭 |
| 换轮盘四个方向的功能 | 改设置项 `radialUp` / `radialRight` / `radialDown` / `radialLeft` 的默认值 |
| 关掉轮盘 | 把设置项 `radialEnabled` 的默认值改为 `false` |
| 改轮盘大小 | 改 `radial.css` 的 `--radial-d`（整个圆环的外直径，默认 `30vh`）；环厚 / 中心圆 / 净空隙 / 字号都由它按比例派生，别去逐个改 px |
| 改轮盘的选中态配色 | 改 `radial.css` 取色段的 `--radial-face-hot`（灰玫瑰）与 `--radial-ink-hot`（玫瑰棕）；想要「整块实色」就把前者改成 `var(--color-accent)`，并把后者一起改浅 |
| 改两圈细线的深浅 | 改 `.radial__edge--out` / `.radial__edge--in` 的 `opacity`（默认 `0.75` / `0.35`）；颜色在取色段的 `--radial-line`（默认莫兰迪雾霾蓝 `#93A8BB`，不跟随主题——想跟随主题就改成 `var(--color-accent)`） |
| 让自定义 UI 按钮触发动作 | 调用 `AliceADVInput.fire("QuickSave")` |
| 在特定页面禁用某个动作 | `AliceADVInput.registerAvailability("OpenMenu", () => 条件)` |
| 覆盖截图实现 | `AliceADVInput.register("Screenshot", fn, { priority: 10 })` |

## 11. 维护约定

- 动作表、绑定语法、轮盘参数以 `style/input.js` 为准；本文档与其不一致时以代码为准并同步修订本文档。
- 新增动作需要同时改三处：`input.js` 的 `ACTIONS`、`theme.json` 的 `input.presets`（视是否给默认绑定）、以及注册处理器的 `script.js` 或 `engine.js`。
- 轮盘的尺寸只在 `radial.css` 里定义（唯一不变量 `--radial-d: 30vh`，其余 `--radial-r-out` / `--radial-r-in` / `--radial-center-d` 按比例派生）；`input.js` **量元素**取生效半径，不得在 JS 里另写一份，也不得 parseFloat 自定义属性（计算值是未化简的 `calc(...)`）。
- 设置项的默认值只写在 `settings.js` 的 `SPECS` 一处；页面不得再写一套默认值。
- 主题变量名一律用连字符写法（`--kebab-case`），由 `builder.py` 与 `theme.js` 两个写入者统一转换。
- 由主题色**派生透明度**（`color-mix(..., transparent)` 之类）时，兜底写法要选对位置：写在**真实属性**上可以用「先 rgba 再 `color-mix`」的两行并列；写在**自定义属性**上不行，必须改用 `@supports` 分支或换一种实现（如 `--color-accent` + `opacity`）。原因见 6.1.2 最后一条。
- CSS 里 `var(--主题变量, 字面兜底)` 的**兜底字面量必须等于模板 `theme.json` 的对应默认值**。写错是静默的（正常主题下兜底分支不触发），只在主题漏配该键时偏色。改模板默认色时把所有兜底一起改（见 6.1.2 最后一条；暂无断言守卫）。
- 轮盘的调色板是**字面莫兰迪值、不跟随主题**（2026-10-01 起）：单色主题（`colors.accent` = `#000000`）下跟随 `accent` 会让选中格 / 细线 / 文字整套变黑白灰。想跟随主题，改 `radial.css` 取色段里对应的变量（`--radial-line` / `--radial-ink` / `--radial-ink-hot` / `--radial-face-hot`）。
