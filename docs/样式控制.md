# 样式控制（theme.json 配置手册）

本文档说明 `theme.json` 暴露的每一个配置项（字段、类型、默认值、作用、限制），以及首页按钮的显示/隐藏机制、自定义主菜单热区的对齐方法。

剧本指令（段/指令/字段）另见 `剧本格式说明.md`；引擎总体设计与页面清单另见 `定义.md`。

## 1. 基本约定

`theme.json` 是用户对引擎的**配置入口**，描述的是**外观与界面**：样式、界面短文案、页面布局、按钮可见性。引擎模板（`aliceadv/src/aliceadv/template/`）的 `theme.json` 是各项默认值的唯一来源。

**不属于 `theme.json` 的（游戏内容，各有其位）**：游戏名与版本在 `info.json`，关于页正文在 `about.txt`，剧本在 `story/`，素材在 `gui/` `images/` `audio/`。内容与配置分开，改样式时不会碰到内容，反之亦然。

| 约定 | 说明 |
|---|---|
| 修改后必须重建 | 改完 `theme.json` 后运行 `aliceadv build <工程目录>`，产物输出到 `<工程>/dist/web/`。未重建不会生效。 |
| 相对值（0~1） | 尺寸/位置类字段若为 0~1 的数字，表示相对于**设计画布**的比例（设计画布由 `screen.designWidth/designHeight` 决定，默认 1920×1080）。构建与运行时都翻译为百分比。 |
| 字符串值 | 若写字符串（如 `"3.4em"`、`"60px"`、`"cover"`），原样透传，不翻译。 |
| 资源路径 | JSON 内写工程根相对路径（如 `gui/main_menu.png`、`images/bg/roof.png`）。**静态 CSS 内**同理写根相对路径，由编译器在构建期按文件深度自动补 `../` 前缀（幂等）。 |
| UI 图片不写进 CSS | 对话框 / 边框 / 按钮 / 画廊占位图等引擎自带图片不在 CSS 里写 `url()`，而是配置在本文件（见 §2.19），运行时由 JS 写入 CSS 变量。改路径只需改 JSON，不必动 CSS。 |
| `_comment` 键 | 任何对象里的 `_comment` 字段仅作说明，构建时忽略，可自由添加。 |
| CSS 变量名 = 键名的 kebab 形式 | 本文件的键名用驼峰（`accentDeep` / `pageHeading`），CSS 变量用 kebab（`--color-accent-deep` / `--size-page-heading`）。构建期与运行期由同一规则换算；键名里的 `_` 也转成 `-`。想在自定义 CSS 里引用某个键，照此拼名即可。 |
| 默认值只有一处 | 各表的「默认值」列即引擎模板 `theme.json` 里的值，也是**唯一**写下的地方。构建时模板与工程 `theme.json` 深度合并（工程优先，见第 6 节）；流程代码（`builder.py` / `theme.js`）不再各存一份字面兜底，最后一道兜底在 CSS 的 `var(--x, 默认)` 里。 |

改配置后若看不到变化，按此顺序排查：① 是否重新构建；② 键名是否写对（错名会被深度合并忽略，不报错）；③ 该键是否在本文件里被标为「保留字段」（见 §2.20）。

## 2. 顶层字段

本节逐个说明顶层字段。菜单页的共享外观 `gameMenu`（整页衬底 + 主内容底板）与 `pages.*` 的逐页覆盖，合并在 §3.7 说明。

### 2.1 screen

定义游戏画布的基础显示参数。

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `aspect` | string | 否 | 画布宽高比，格式 `"16:9"`。**不参与布局计算**：画布比例由 `designWidth/designHeight` 决定，本字段只作为可自行引用的信息变量 `--aspect` 写出 | `"16:9"` |
| `designWidth` | number | 否 | 设计画布宽（像素），所有内部尺寸以此为基准等比例缩放，并作为舞台整体缩放的基准 | `1920` |
| `designHeight` | number | 否 | 设计画布高（像素） | `1080` |
| `overflowColor` | string | 否 | 画布之外溢出区域的填充色（CSS 颜色） | `"#0d0d10"` |

`designWidth/designHeight` 同时决定自定义热区坐标 `left/top/width/height` 的归一化基准。主菜单背景图建议按此分辨率制作（如 1920×1080）。

改小 `designWidth/designHeight` 不会让画面变小：布局按新基准排、舞台按新基准缩放，两者相抵，最终渲染尺寸由窗口决定（例如 1280×720 的画布与 1920×1080 的画布在同一窗口下渲染结果一致）。

### 2.2 fonts

配置四类文字的字体。四类角色：

| 角色 | 用途 |
|---|---|
| `text` | 对话 / 旁白正文 |
| `interface` | 界面文字（菜单、按钮、提示） |
| `title` | 标题类文字（主菜单标题、页面标题） |
| `system` | 系统文字（跳过提示、错误信息），一般用系统字体栈 |

每个角色有两种写法：

写法一，字符串（系统 / Web 字体栈）：

```json
{
  "fonts": {
    "text": "\"PingFang SC\", \"Microsoft YaHei\", sans-serif",
    "system": "system-ui, -apple-system, \"PingFang SC\", sans-serif"
  }
}
```

写法二，对象（自定义字体文件）：

```json
{
  "fonts": {
    "text": {
      "family": "SourceHanSansLite",
      "src": "fonts/SourceHanSansLite.ttf",
      "fallbacks": "\"PingFang SC\", \"Microsoft YaHei\", sans-serif"
    }
  }
}
```

| 字段（对象写法） | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `family` | string | 是 | `@font-face` 字体族名 | — |
| `src` | string | 是 | 字体文件路径（工程根相对） | — |
| `fallbacks` | string | 否 | 兜底字体栈，加载失败时降级 | — |

自定义字体文件放在工程 `fonts/` 下，构建时复制到 `dist/web/fonts/` 并生成 `@font-face`。同一 `(family, src)` 自动去重。

### 2.3 colors

颜色变量，供 CSS 变量 `--color-<key>` 使用。键名如下，全部可选，缺省使用引擎内置值。`text` 与 `interface` 是**两个不同层级**，不要合并：前者用于剧本正文（台词、角色名、历史回看、存档摘要、关于页正文），后者用于界面文字（菜单纸面板、按钮、列表项、存档槽元信息、提示条）。

| 键 | CSS 变量 | 用途（主要消费者） |
|---|---|---|
| `accent` | `--color-accent` | 主强调色：页面标题、当前页高亮、选中块、滑块、设置页分区左边条与半透明描边/衬底（描边用 `color-mix()` 从本键现算） |
| `accentDeep` | `--color-accent-deep` | 深一档的强调色：翻页器当前页、选中块的悬停态 |
| `idle` | `--color-idle` | 空闲态文字 / 纸感按钮文字 |
| `idleSmall` | `--color-idle-small` | 次要空闲文字（设置页说明、存档槽时间） |
| `hover` | `--color-hover` | 悬停色：纸感按钮、列表项、复选框、滚动条 |
| `selected` | `--color-selected` | 选中态文字色：纸感按钮 `.is-selected` |
| `insensitive` | `--color-insensitive` | 禁用 / 失效态文字色（设置页禁用的分段按钮） |
| `text` | `--color-text` | 正文文字色：对话框台词与角色名、历史回看、存档摘要、关于页正文 |
| `interface` | `--color-interface` | 界面文字色：body 默认、菜单纸面板、按钮、章节/分支/画廊列表项、存档槽元信息、提示条 |
| `paper` | `--color-paper` | 纸感面板底色：存档槽纸面、撕裂边、滑块手柄 |
| `paperDeep` | `--color-paper-deep` | 深一档纸色：开始页兜底底纹、纯色兜底页、存档槽缩略图占位底色 |
| `muted` | `--color-muted` | 弱化的强调色：翻页器数字 |
| `hoverMuted` | `--color-hover-muted` | 弱化的悬停色：翻页器数字悬停 |

示例：

```json
{
  "colors": {
    "accent": "#3B5998",
    "text": "#402000",
    "paper": "#FAF8F0"
  }
}
```

| `sprite` | `bottom` `height` | 立绘贴底偏移 / 高度（`"auto"` 自适应） | `0.00 / "auto"` |
| `nvl` | `left` `width` `lineGap` `justify` `textAlign` | NVL 整屏旁白布局 | `0.1875 / 0.625 / "0.5em" / "center" / "left"` |

| `toolbar` | `height` `gap` | 底部工具栏高度与间距 | `"6.5em" / "2em"` |

### 2.14 panel（游戏内暂停菜单浮层）

游戏内暂停菜单 = 点击舞台底部「菜单」按钮（或按 ESC）弹出的浮层。它的按钮、停靠方向、窗口尺寸都由 `panel` 控制。

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `side` | string | 否 | 浮层停靠方向：`"left"` / `"right"` / `"center"` | `"right"` |
| `width` | number | 否 | 浮层窗口宽（**px**，相对 `screen.designWidth` 转换为比例，构建期翻译）。`center` 停靠时即居中宽度 | `500` |
| `height` | number | 否 | 浮层窗口高（**px**，相对 `screen.designHeight` 转换为比例）。缺省为整屏高（顶部到底部贯穿） | 整屏高 |
| `buttons` | string[] | 否 | 浮层按钮顺序。键见 §2.18 可选键，另支持 `title`（回到首页）与 `back`（返回 / 关闭浮层）。未列出的不显示 | `["save","load","settings","chapters","gallery","about","title","back"]` |

`width` / `height` 的 px→比例换算与 定义.md「按钮以 px 为单位 → 比例」一致：例如 `screen.designWidth=1920` 时 `width:500` 即 `500/1920≈26%`。设置 `height` 后浮层变为垂直居中的定高窗口（不再贯穿整屏）。

```json
{
  "panel": {
    "side": "right",
    "width": 500,
    "buttons": ["save", "load", "settings", "chapters", "gallery", "about", "title", "back"]
  }
}
```

### 2.15 notifyYpos / skipYpos

对应 Ren'Py 的 `gui.notify_ypos` / `gui.skip_ypos`：两种提示条**距舞台顶部**的距离，单位为设计像素（相对 `screen.designHeight` 换算为百分比）。

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `notifyYpos` | number | 否 | 通知条（`.notify`）距顶距离 | `68` |
| `skipYpos` | number | 否 | 快进指示条（`.skip-indicator`）距顶距离 | `15` |

两条提示条都**水平铺满舞台**（`left: 0; right: 0`），靠内的 `flex` 对齐决定内容落点：通知条居中、快进指示条靠左。

| 提示条 | 触发方式 | 内容 | 消失方式 |
|---|---|---|---|
| 通知条 `.notify` | `AliceADVEngine.notify(text, ms)`；引擎在「读档成功」时自动调用 | 一行文字 | 默认 1600ms 后自动隐藏（`ms` 可指定） |
| 快进指示条 `.skip-indicator` | 播放中开启快进（舞台底部工具栏的「快进」） | 「快进中」+ 三个依次闪烁的三角 | 快进关闭即隐藏 |

两个元素都由 `theme.js` 的 `buildStagePage()` 随舞台骨架一次性建好，运行时只切换 `.is-active`，因此舞台重建（换主题 / 重新 `buildAll()`）不会丢。`notify()` 在循环里连续调用时以最后一次为准（不排队）。

外观（衬底、字号、飘字动画）写在 `style/pages/stage.css`，复用 `--gui-frame` 作为背景图；未接九宫格时该图整体拉伸显示。

### 2.16 info

游戏基本信息。**本节字段通常不必写**：游戏名与版本的唯一位置是工程根 `info.json`（见第 6 节）。

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `name` | string | 否 | 游戏名（首页标题 / 关于页显示） | — |
| `version` | string | 否 | 游戏版本号 | — |

构建时 `theme.info` 由 `info.json` 合并而成（模板 `info.json` ⊕ 工程 `info.json`），运行时读 `theme.info` 即等于 `info.json` 的内容。**引擎模板的 `theme.json` 不再重复这两个字段**（2026-09-27 起）；写在这里也会被 `info.json` 覆盖，没有意义。

**引擎版本不在此配置。** 引擎版本取自打包的引擎包（`aliceadv/src/aliceadv/__init__.py` 的 `ENGINE_NAME` / `ENGINE_VERSION`，版本号唯一来源为同目录 `_version.py`），构建时与仓库地址 `ENGINE_REPO` 一起写入产物的 `window.__ENGINE__`（字段 `name` / `version` / `repo`）。

游戏内版本显示规则：首页只显示「游戏版本」（`info.version`）；关于页把「游戏版本」与「引擎 aliceADV vX.Y.Z」放在**同一个圆角框里排成一行**，其中**「引擎名 + 版本号」整体是指向 `ENGINE_REPO` 的链接**（链接不带下划线，仅 hover 变色）。**两处的游戏版本都带 `v` 前缀**（`theme.js` 的 `verLabel()` 统一补，配置里已经写成 `v0.2.2` 也不会变成两个 v）。模板模式（未构建）没有 `window.__ENGINE__`，因此不显示「引擎」那一项、也不出那个框。

### 2.17 关于页正文：工程根 about.txt（不是 theme.json 字段）

关于页的正文（游戏简介、制作人员、版权声明这类长篇文本）**不在 `theme.json` 里配置**，而是放在**工程根 `about.txt`**，一个 UTF-8 纯文本文件。正文按换行切成「一行一个块」渲染：**换行与空行逐行原样保留，一个空行 = 一个高度等于一行文字的块**。

**换行规则**（2026-09-29 定稿；第一版用 `split(/\n+/)` 一刀切分段，空一行与空两行无法区分；第二版用 `margin` 段距，但段距与正文行高无关、看着差别很小；最终改为 pre-wrap 逐行还原）：

| 写法 | 渲染结果 |
|---|---|
| 换行（`\n`） | 同段内换行；长行仍按栏宽自动折行 |
| 空 1 行 | 一个空行盒，**高度正好等于一行文字**（`line-height`） |
| 空 ≥2 行 | 多个空行盒，高度 = 对应行数 × `line-height` |

也就是说：作者在文件里写几个空行，纸上就留出几行文字高度的空白，**不再用任何人为指定的段距数值**。

| 项 | 说明 |
|---|---|
| 位置 | `<工程目录>/about.txt` |
| 编码 | UTF-8 |
| 分段 | 见上面的换行规则；正文整体作为一个 `pre-wrap` 容器，逐行还原 |
| 获取方式 | 构建产物：`builder` 读取后内联为 `window.__ABOUT__`（`file://` 可直接打开）；模板模式（未构建，直接开模板目录）：`theme.js` 运行时 `fetch("about.txt")` |
| 缺失 / 为空 | 关于页只显示游戏名与版本行（游戏版本 + 引擎），不出正文 |

为什么正文不写在 `theme.json` 里：`theme.json` 描述的是**外观与界面**（尺寸、颜色、字体、图片、页面布局、按钮可见性、界面短文案）。超长的、随游戏走、只增不改的正文属于**游戏内容**，和剧本（`story/`）、素材（`gui/` `images/` `audio/`）一样各自占一个文件，才能让「改样式的文件」和「改内容的文件」互不干扰。

**废弃说明**：旧版把正文写在 `theme.json` 顶层 `about`。该键已废弃——构建时若发现它、且工程根没有（或为空）`about.txt`，仍会沿用其值并打印迁移提示，已迁移的工程不受影响。`about.txt` 有内容时永远优先。

### 2.18 sidebar

`string[]`。游戏内通用菜单页（存档 / 读档 / 设置 / 章节 / 分支 / 画廊 / 关于）左侧（或右侧）的导航按钮顺序。只列出想显示的键，顺序即显示顺序；未列出的按钮不显示。

可选键：`save` `load` `settings` `chapters` `gallery` `branches` `about` `back`。

```json
{
  "sidebar": ["save", "load", "settings", "chapters", "gallery", "branches", "about", "back"]
}
```

限制：本键只控制「游戏内通用菜单页的侧栏」。游戏内按 ESC 弹出的暂停菜单（浮层）是另一套配置，见 §2.14 `panel`。

**侧边栏默认不列 `history`**（2026-09-26 起）。历史记录是播放内的功能，入口在舞台底部工具栏（`pages.stage.toolbar`）；挂在菜单页侧栏上会多出一个语义错位的入口。引擎仍认识 `history` 这个键（工具栏在用），写进 `sidebar` 也会渲染，但默认配置与模板都不列它。

### 2.19 UI 图片资源（数据驱动）

引擎自带的界面图片（对话框、面板边框、按钮、画廊占位图）统一在本文件配置，CSS 里不写 `url()`。改图只需改 JSON；预加载器与渲染读同一份配置，不会出现「CSS 有图、预加载看不见」的漏载。

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `dialog.background` | string | 否 | 默认对话框背景图（角色可用 `characters.json` 的 `textbox` 覆盖） | `"gui/textbox.png"` |
| `frame.background` | string | 否 | 面板边框底图（存档槽 / 历史 / 暂停浮层） | `"gui/frame.png"` |
| `button.idle` | string | 否 | 通用按钮空闲态背景图 | `"gui/button/idle_background.png"` |
| `button.hover` | string | 否 | 通用按钮悬停态背景图 | `"gui/button/hover_background.png"` |
| `choice.idle` | string | 否 | 对话选项空闲态背景图 | `"gui/button/choice_idle_background.png"` |
| `choice.hover` | string | 否 | 对话选项悬停态背景图 | `"gui/button/choice_hover_background.png"` |
| `thumb.placeholder` | string | 否 | 画廊条目默认缩略图 | `"gui/sample_thumb.png"` |

三段共用同一份数据源：

| 环节 | 读取方 | 行为 |
|---|---|---|
| 渲染 | `theme.js` 的 `applyThemeVars()` | 写入 CSS 变量 `--gui-textbox` `--gui-frame` `--gui-button-idle` `--gui-button-hover` `--gui-choice-idle` `--gui-choice-hover` |
| 样式 | `base.css` / `pages/*.css` | 以 `background-image: var(--gui-*)` 引用 |
| 预加载 | `preload.js` 的 `collectChrome()` | 从同一批字段收集路径，启动时预载 |

字段缺省时使用模板默认值（构建期合并，见第 6 节）；显式写 `null` 或 `""` 表示不设图片。

维护提示：变量写入的是**绝对 URL**（基于 `index.html` 所在目录解析）。若改成裸相对路径，会因 CSS 文件层级不同（`style/` 与 `style/pages/`）被解析到错误目录，导致图片 404。

### 2.20 保留字段（写在 theme.json 里但引擎尚未消费）

以下字段可以写、不会报错，但**当前不产生任何效果**。它们随模板 `theme.json` 一并带来，逐项对应 Ren'Py `gui.rpy` 里的同名默认值（`gui.*_borders` / `gui.*_tile` / `gui.*_text_idle` / …），保留是为了让工程侧配置能与 Ren'Py 一一对照。

注意：`aliceadv gui2theme` **不产出**这些字段（它只翻译几何与字号，见其 docstring 的换算表）。改了 `gui.rpy` 的 `gui.button_borders` 不会让 `theme.json` 跟着变，需要手工同步。依赖它们之前请先确认引擎版本。

| 字段 | 现状 |
|---|---|
| `frame.borders` / `frame.confirmBorders` / `frame.tile` | 九宫格切图的边界与平铺信息。引擎目前把界面图整体拉伸显示（`background-size: 100% 100%`），不做九宫格切片。 |
| `button.borders` / `button.tile` | 同上，作用于按钮背景图。 |
| `choice.borders` | 同上，作用于选项背景图。 |
| `slot.borders` | 同上，作用于存档槽边框图。 |
| `slider.tile` / `slider.borders` | 同上，作用于滑块图。 |
| `scrollbar.tile` / `scrollbar.borders` / `scrollbar.unscrollable` | 同上；滚动条由 CSS 自绘，`unscrollable`（不可滚动时隐藏）未实现。 |
| `button.textIdle` / `button.textHover` / `button.textSelected` | 纸感按钮的三态文字色。实际取自 `colors.idle` / `colors.hover` / `colors.selected`——改按钮文字色请改这三个。 |
| `choice.idleColor` / `choice.hoverColor` | 选项按钮的文字色，同上取自 `colors.idle` / `colors.hover`。 |
| `screen.aspect` | 仅作为信息变量 `--aspect` 写出。画布比例由 `designWidth/designHeight` 决定，本字段不参与计算。 |

`pages.<页>.autoSlots`（自动存档槽位数）已于 2026-09-27 **删除**，不再是一个可写字段：它对应 Ren'Py 的引擎级配置 `config.autosave_slots`（自动存档在 N 个槽位里轮转），而本引擎只有一个自动存档槽，槽位总数由 `slotCols × slotRows` 决定。原值 `9` 与实际布局（3×2 = 6 格）直接矛盾，且运行时从未读过它。

九宫格这一组还有个前提：`border-image` 必须有**一张可切的图片**。当前只有 `frame.background`、`button.idle/hover`、`choice.idle/hover` 有对应贴图；`slot`（由 CSS 自绘：底色 + 噪点 + 四个角块 `div`）、`slider`、`scrollbar` 都**没有图片键**，所以后三组的 `borders` / `tile` 即便接上 `border-image` 也无图可切——要接先得给它们补图片字段。

**已接上的（不再属于保留字段）**：

- `notifyYpos` / `skipYpos` —— 2026-09-27 起分别由 `.notify` 与 `.skip-indicator` 消费（`--notify-ypos` / `--skip-ypos`），详见 §2.15。
- `layout.name.anchor` 是 Ren'Py `gui.name_xalign` 的等价物，2026-09-27 起由 `--name-anchor` 消费。
旧版 `gui2theme` 把它折算成 `layout.name.align: "left"|"center"|"right"` 并且引擎没人读（名字框的位置固定按左缘贴合），
现已改为直接输出锚点小数（`0`/`0.5`/`1`/`0.35`…）并接上消费者——折算成三个词会丢掉中间值。

模板 `theme.json` 里还有三个引擎自带的贴图变量（`--paper-noise`、`--torn-top`、`--torn-bottom`），写在 `style/base.css` 的 `:root` 里，属于引擎内建纹样，不开放配置。

`pages` 下每个键对应一个页面对象。通用字段：

### 3.1 pages.title（首页）

首页是配置项最多的页面，详见第 4、5 节。

### 3.2 pages.save / pages.load

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `background` | string | 否 | 背景图 | `"gui/game_menu.png"` |
| `title` | string | 否 | 中文标题 | `"保存"` / `"读取"` |
| `titleEn` | string | 否 | 英文副标题 | `"Save"` / `"Load"` |
| `slotRows` | number | 否 | 槽位行数（实际生效） | `2` |

### 3.3 pages.settings

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `background` | string | 否 | 背景图 | `"gui/game_menu.png"` |
| `title` / `titleEn` | string | 否 | 中文标题 / 英文副标题 | `"设置"` / `"Preferences"` |
| `sections` | array | 否 | 设置项的分区、顺序与文案。不写时引擎把全部已登记设置项按登记顺序铺成一页 | — |

`sections` 的元素为 `{ title, items }`，`items` 的每条既可以引用一个设置项（`key` 必填，另有 `label` / `chipLabel` / `hint` / `full` / `options`），也可以写成 `{ "type": "keymap" }` 插入按键映射区块：

```json
{
  "pages": {
    "settings": {
      "sections": [
        { "title": "操作", "items": [
          { "key": "wheelReview", "label": "滚轮回看", "chipLabel": "滚轮回看" },
          { "key": "radialHoldMs", "label": "轮盘触发时长", "full": true }
        ] },
        { "title": "按键映射", "items": [
          { "type": "keymap", "title": "按键 / 鼠标 / 滚轮 / 手柄" }
        ] }
      ]
    }
  }
}
```

两点约束：

- 控件形态（开关 / 滑块 / 分段 / 下拉框）与取值来源由 `style/settings.js` 的 `SPECS` 决定，`sections` 只决定**显示哪些、什么顺序、什么文案**。`key` 未在 `SPECS` 登记时该条被跳过并打印告警。
- 设置项的存在性与默认值只写在 `SPECS` 一处，页面不写第二套默认值。

字段级说明与设置项类型表见 [输入与按键](输入与按键.md) 第 7 节。

### 3.7 菜单页两层衬底与布局：gameMenu（共享默认）与 pages.*（单页覆盖）

游戏内菜单页（`save` / `load` / `settings` / `chapters` / `branches` / `gallery` / `about`）采用同一套版式与衬底：

- 版式 = **侧栏 / 主内容双栏**，页面四周（侧栏外侧、主内容外侧）是一圈较宽的外侧留白；
- 衬底 = **两层**：`gameMenu.backgroundColor` 的半透明整页衬底（把背景图压淡）+ 白色菜单底。第二层分成两个**各管一块**的键：`gameMenu.panelColor` 只落在**主内容那一整块面板**上（**略微透明**，底图淡淡透出）；`gameMenu.sidebarButtonColor` 落在**侧栏的每个按钮各自**身上（默认**纯白、完全不透明**）。**关于页是例外**：那一页没有主内容面板，`panelColor` 落在包住正文栏的那块纸上（见本节末尾 `pages.about`）。
- 侧栏**本身不铺任何底色**（`background` 与 `box-shadow` 都没有）。原因：整块面板会把几个导航按钮和底部「返回」连成一片，看不出是独立按钮。按钮的「体积」由自身纵向内边距提供，范围另由一条**非黑描边**勾出（描边色取 `colors.muted`：模板 `#6080D0`、本示例 `#666666`，都不是纯黑）——去掉侧栏衬底后仅靠描边在饱和底图上读不清，所以按钮单独铺一层不透明的白。

三个颜色默认值写在**顶层 `gameMenu`** 里，所有菜单页共享：

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `gameMenu.backgroundColor` | string | 否 | 整页半透明衬底（`.page__tint`，铺在背景图之上、内容之下）。支持 `rgba()` | `rgba(255, 255, 255, 0.4)` |
| `gameMenu.panelColor` | string | 否 | 主内容那一整块面板的底色（略微透明）。支持 `rgba()`。侧栏不用它 | `rgba(255, 255, 255, 0.85)` |
| `gameMenu.sidebarButtonColor` | string | 否 | 侧栏**每个按钮各自**的底色，默认完全不透明。支持 `rgba()` | `#FFFFFF` |

```json
{
  "gameMenu": {
    "backgroundColor": "rgba(255, 255, 255, 0.4)",
    "panelColor": "rgba(255, 255, 255, 0.85)",
    "sidebarButtonColor": "#FFFFFF"
  }
}
```

**单页覆盖**：在 `pages.<页>.backgroundColor` / `pages.<页>.panelColor` / `pages.<页>.sidebarButtonColor` 写同名字段即可覆盖该页（例：只给关于页更厚的衬底）。写 `null` 表示**不要该层**——背景图直接透出（`sidebarButtonColor` 写 `null` 时按钮只剩描边、没有底色）。

**三个默认值只有一处书写位置**：引擎模板的 `theme.json`（即上表右列）。构建时 `_deep_merge(模板, 工程)` 把三者合成生效配置内联进产物，工程没写就用模板的值——所以 `theme.js` 里不各留一份兜底常量（`game-menu.css` 只用 `var(--game-menu-panel, transparent)` / `var(--game-menu-sidebar-btn, #fff)` 作最后兜底）。

衬底不透明度是纯观感取舍：`panelColor` 调到 `1` 完全不透（最干净，但失去「底图淡透」的层次）；默认 `0.85` 是「略微透明」。侧栏按钮的 `sidebarButtonColor` 默认不透明，正是为了让按钮在任意背景图上都读得清；想让它跟随背景图、只留描边，把它设成 `transparent` 即可。

整页衬底 `backgroundColor` 调高（如 `0.9`）背景只剩极淡底纹；调低（如 `0.4`）能看清背景图，但**若该页背景图里烤进了文字**（典型：`gui/main_menu.png` 上带「开始游戏 / 读取」等按钮字）就会透出来干扰阅读。此时代替方案是给该页单独换一张干净背景图，或按需调高 `backgroundColor`。

#### 版式尺度（写在 CSS，非 theme.json）

侧栏列宽与外侧留白是引擎固定版式，写在 `style/pages/game-menu.css` 的 `.game-menu` / `.game-menu__divider` 规则里（设计像素，1920×1080 基准）：

| 变量 | 含义 | 值 |
|---|---|---|
| `--menu-side-w` | 侧栏列宽 | `16%` |
| `--menu-pad-x` | 页面左右外侧留白（侧栏左边、主内容右边） | `56/1920` |
| `--menu-pad-y` | 页面上下留白 | `32/1080` |
| `--menu-gap` | 侧栏与主内容之间的缝（分隔线落在缝中间） | `18/1920` |

要改版式改这四个变量即可。注意它们必须同时定义在 `.game-menu` 与 `.game-menu__divider` 上：分隔线是 `.game-menu` 的兄弟节点（直接挂在页面根上），只写在 `.game-menu` 上它继承不到。

#### pages.about

关于页的**版式与其他菜单页不同**：正文按**固定栏宽**排成一列，白底（纸）**只包住这一列**、不铺满主区，整块纸在侧栏右侧的区域里**水平居中**；纸的左右两侧不放任何面板，直接看到整页衬底 `gameMenu.backgroundColor` 那一层。

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `background` | string | 否 | 页面背景图 | `"gui/main_menu.png"` |
| `backgroundColor` | string | 否 | 覆盖 `gameMenu.backgroundColor`（整页衬底；纸的左右两侧看到的就是它） | 同 `gameMenu` |
| `panelColor` | string | 否 | 覆盖 `gameMenu.panelColor`（**本页它是那张纸的底色**，不是主内容区的底色） | 同 `gameMenu` |
| `sidebarButtonColor` | string | 否 | 覆盖 `gameMenu.sidebarButtonColor`（侧栏每个按钮各自的底色） | 同 `gameMenu` |

版本行按「游戏版本 v`info.version` ｜ 引擎 aliceADV v`ENGINE_VERSION`」渲染：两个版本号都带 `v` 前缀（由 `theme.js` 的 `verLabel()` 统一补，配置里写成 `v0.2.2` 也不会出现两个 v）。

纸张的尺寸与留白写在 `style/pages/about.css` 的 `.page_about` 规则里（设计像素）：

| 变量 | 含义 | 值 |
|---|---|---|
| `--about-sheet-content` | **正文栏宽**（决定「一行放多少字」） | `900/1920` |
| `--about-sheet-gap` | 纸四周留白（设 `0` 则上下贴边） | `24/1080` |
| `--about-sheet-pad-y` / `--about-sheet-pad-x` | 纸内文字的页边距（横向同时决定纸比正文栏宽出多少） | `64/1080` / `56/1920` |

纸宽 = `--about-sheet-content` + `2 × --about-sheet-pad-x`（全局 `box-sizing: border-box`，所以纸的内容盒正好是 `--about-sheet-content`），纸高 = 主内容区高度减去 `--about-sheet-gap`。正文比纸高时在**纸内滚动**（滚动条贴在纸的右边缘）。

要改「一行放多少字」就改 `--about-sheet-content`，别去改 `--about-sheet-pad-x`——后者一改纸宽会跟着变，纸的宽度是围着正文栏算的。

> ⚠️ **不要用 `aspect-ratio` 给纸定 A4 比例**。纸高是固定的（主区高 − 留白 ≈ 968），一旦用比例算纸宽，纸宽就被锁成 684、扣掉内边距栏宽只剩 572，换行位置相对 900 那一档全面错位；从现象上看很像「文字被放大了」，但字号其实一个字都没改（工程 `sizes.interface` 前后一致）。2026-09-27 踩过这个坑，2026-09-28 改回定宽并加了断言守住。

## 4. 首页布局：pages.title

### 4.1 layout

`string`。可选值 `left` / `center` / `right` / `bottom` / `custom`。

| 值 | 说明 |
|---|---|
| `left` | 左侧白底栏 + 右侧背景图，按钮靠左 |
| `center` | 按钮居中堆叠，无白色底 |
| `right` | 右侧白底栏，按钮靠右 |
| `bottom` | 按钮在底部一排，上方为全屏背景 |
| `custom` | 使用 `customButtons` 图片热区，完全替代默认按钮列表 |

### 4.2 background / showName / showVersion

| 字段 | 类型 | 说明 | 默认 |
|---|---|---|---|
| `background` | string | 首页背景图路径 | `"gui/main_menu.png"` |
| `showName` | boolean | 是否显示游戏名 | `true` |
| `showVersion` | boolean | 是否显示版本号（游戏名下方显示游戏版本，形如 `v0.2.2`） | `true` |

首页只显示游戏版本。引擎版本在「关于」页显示（见 §2.16）。

### 4.3 buttons（文字按钮列表，控制显示/隐藏）

`string[]`。首页默认按钮列表。**只列出要显示的键，顺序即显示顺序；未列出的按钮不渲染。** 这是控制首页按钮「显示/隐藏」的第一种机制。

支持的键：`start` `continue` `load` `settings` `chapters` `gallery` `branches` `about` `quit`。

默认顺序：

```json
{
  "pages": {
    "title": {
      "layout": "left",
      "buttons": ["start", "continue", "load", "settings", "chapters", "gallery", "branches", "about", "quit"]
    }
  }
}
```

隐藏画廊按钮：从数组中删除 `"gallery"` 即可。隐藏分支按钮：删除 `"branches"`。隐藏继续按钮：删除 `"continue"`。

### 4.4 customButtons（图片热区，完全替代 buttons）

`object[]`。配置后，**`buttons` 列表不再渲染**，首页按钮改为背景图上的透明/图片热区。这是控制首页按钮「显示/隐藏」的第二种机制，且能精确对齐主菜单美术图上的按钮。

每个热区对象的字段：

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `action` | string | 是 | 按钮功能，见 4.5 取值表 | — |
| `left` | number | 是 | 热区左缘（0~1，相对设计画布宽） | — |
| `top` | number | 是 | 热区上缘（0~1，相对设计画布高） | — |
| `width` | number | 是 | 热区宽（0~1） | — |
| `height` | number | 是 | 热区高（0~1） | — |
| `image` | string | 否 | 按钮图片（工程根相对）；提供后渲染为图片按钮 | — |
| `hover` | string | 否 | 悬停态图片；需配合 `image` | — |
| `label` | string | 否 | 无 `image` 时的文字标签（叠在热区上） | — |

示例：

```json
{
  "pages": {
    "title": {
      "layout": "custom",
      "background": "gui/main_menu.png",
      "showName": false,
      "showVersion": false,
      "customButtons": [
        { "action": "start",    "left": 0.02, "top": 0.70, "width": 0.22, "height": 0.10 },
        { "action": "continue", "left": 0.02, "top": 0.57, "width": 0.20, "height": 0.10 },
        { "action": "load",     "left": 0.02, "top": 0.83, "width": 0.20, "height": 0.10 },
        { "action": "settings", "left": 0.76, "top": 0.72, "width": 0.20, "height": 0.10 },
        { "action": "about",    "left": 0.80, "top": 0.30, "width": 0.12, "height": 0.08 },
        { "action": "quit",     "left": 0.82, "top": 0.14, "width": 0.10, "height": 0.07 }
      ]
    }
  }
}
```

坐标语义：`left/top/width/height` 是相对整张背景图（设计画布 1920×1080）的归一化值。例如 `left:0.02, top:0.70, width:0.22, height:0.10` 表示热区左缘在 2% 宽度处、上缘在 70% 高度处、宽 22%、高 10%。

### 4.5 首页按钮 action 取值表

| action | 跳转 / 行为 | 备注 |
|---|---|---|
| `start` | 开始游戏（第一个可玩章节） | 自动绑定首章剧本 |
| `continue` | 从自动存档继续 | 自动存档关闭或无存档时按钮置灰失效；显示与否由列表/`customButtons` 控制 |
| `load` | 打开读取页 | 标签为「读取」 |
| `settings` | 打开设置页 | — |
| `chapters` | 打开章节选择页 | — |
| `gallery` | 打开画廊页 | — |
| `branches` | 打开剧情分支页 | 多数游戏不提供，不列即可 |
| `about` | 打开关于页 | — |
| `help` | 同 `about` | 兼容「主菜单放 Help」的游戏 |
| `quit` | 退出确认弹窗 | — |

其中 `continue` 的特殊性：它的「有效性」由存档系统决定（自动存档开启且存在自动存档才可用），但「是否显示」完全由你是否在 `buttons` / `customButtons` 中列出决定——引擎不擅自隐藏它。若已关闭自动存档（`info.json` 的 `autoSave:false`），应在 `theme.json` 中自行移除 `continue`，否则首页会显示一个置灰、点击无效的按钮。

### 4.6 backgroundSize（热区对齐关键）

`string`。首页背景图的铺满方式。

| 值 | 说明 | 适用 |
|---|---|---|
| `"cover"` | 保持比例铺满，可能裁切 | 装饰性背景、普通布局 |
| `"contain"` | 保持比例完整显示，可能留边 | 需完整看到图片内容 |
| `"100% 100%"` | 拉伸铺满整张画布，1:1 映射坐标 | 自定义热区（`customButtons`）默认 |

**自定义热区模式下，默认值为 `"100% 100%"`**，即背景图被精确映射到设计画布，使 `customButtons` 的 0~1 坐标与图片像素 1:1 对应，从而保证热区与图上按钮严格对齐。若你的主菜单图不是 16:9，请显式指定 `backgroundSize`：

```json
{
  "pages": {
    "title": {
      "layout": "custom",
      "background": "gui/main_menu.png",
      "backgroundSize": "100% 100%",
      "customButtons": [ ... ]
    }
  }
}
```

建议：主菜单背景图直接按 `screen` 设定的分辨率（默认 1920×1080）制作，此时 `cover` 与 `100% 100%` 等价，且热区坐标计算最直观。

### 4.7 debugHotzones（对齐调试）

`boolean`。设为 `true` 时，每个自定义热区显示红色虚线边框与 `action` 名称，便于核对热区是否准确覆盖图上按钮。

```json
{
  "pages": {
    "title": {
      "layout": "custom",
      "debugHotzones": true,
      "customButtons": [ ... ]
    }
  }
}
```

调试完成后改为 `false` 或删除该键即可。

## 5. 首页按钮显示/隐藏：两种机制对照

| 机制 | 配置位置 | 控制方式 | 适用场景 |
|---|---|---|---|
| 列表法 | `pages.title.buttons` | 数组里只保留要显示的键 | 文字按钮、需要统一风格 |
| 热区法 | `pages.title.customButtons` | 数组里只保留要显示的热区；配置后 `buttons` 失效 | 主菜单美术图自带按钮、需像素对齐 |

两种方法都支持 `gallery` / `branches` / `settings` / `about` 等按钮的显示与隐藏——从对应数组中删除该键即可。引擎不会写死任何默认按钮，首页只渲染你在 `theme.json` 中显式列出的按钮。

## 6. info.json 覆盖字段与构建期默认值合并

构建时 `theme.json` 与工程根 `info.json` 都会与引擎模板深度合并，`info.json` 的下列键并入 `theme.info` 后优先生效：

| 键 | 说明 |
|---|---|
| `name` `version` | 游戏名 / 游戏版本 |
| `autoSave` | 是否启用自动存档（默认 `true`） |
| `quickSave` | 是否启用快速存档（默认 `true`） |
| `preload` | 预加载策略（`boot` / `runtime` / `lookahead` / `chapter` / `stage` / `fastForward` / `fallback` / `timeout` / `onTimeout` / `slowSpeedKBps`），见 `信息配置.md` §5；机制原理见 `预加载.md` |

引擎版本不由本文件配置，来自引擎包本身。

关于页正文同样不由本文件配置，来自工程根 `about.txt`（见 §2.17）。它**不参与深度合并**：内容不继承引擎默认值，工程里怎么看就怎么渲染。

`autoSave` / `quickSave` 关闭后的连锁影响：

| 开关 | 影响 |
|---|---|
| `autoSave:false` | 自动存档槽从存档/读档页消失；首页「继续」按钮置灰失效；但按钮是否显示仍由 `theme.json` 决定 |
| `quickSave:false` | 快速存档槽从存档页消失；菜单「快存 / 快读」与工具栏对应按钮失效 |

## 7. 自定义主菜单热区对齐工作流

1. 按 `screen.designWidth × designHeight`（默认 1920×1080）制作主菜单背景图，图上按钮位置即最终位置。
2. 用图像工具量出每个按钮的像素坐标，换算为 0~1：
   - `left = 按钮左缘像素 / 画布宽`
   - `top = 按钮上缘像素 / 画布高`
   - `width = 按钮宽像素 / 画布宽`
   - `height = 按钮高像素 / 画布高`
3. 在 `pages.title.customButtons` 中按 `action` 填入上述坐标，设 `layout:"custom"`。
4. 临时设 `debugHotzones:true` 构建预览，核对红框是否准确覆盖图上按钮；偏差则回到第 2 步微调。
5. 核对无误后设 `debugHotzones:false`，并确认 `backgroundSize` 为 `"100% 100%"`（自定义模式默认即此值）。

注意：热区坐标是相对整张画布（0~1），不是相对某个局部容器。只要背景图按设计分辨率制作且 `backgroundSize` 为 `100% 100%`，热区与图上按钮必然 1:1 对齐。

## 8. 维护约定（重要）

`theme.json` 的每一项都对应 `theme.js`（`buildTitlePage` / `applyThemeVars` 等）与构建机制（`builder.py`）的具体实现。以下规则适用于本仓库：

- 修改 `theme.js`、`engine.js`、构建机制，或新增 / 修改 `theme.json` 的字段、语义时，**必须同步更新本文档**，并在变更说明中明确指出「引擎已更新 + 文档已更新」。
- 本文档唯一副本位于引擎仓库 `docs/样式控制.md`，随仓库发布为文档站 <https://alice-drop.github.io/aliceADV/>。引擎包（`aliceadv`）与用户工程都不含本文档。
- 任何字段新增时，在对应小节补充字段表（类型 / 必填 / 说明 / 默认值）；任何字段废弃时，在表中标注「当前未消费」而非直接删除说明，避免读者误解。
- **新增配置项前先分清「外观」还是「内容」**。本文件只描述外观与界面；长篇、随游戏走、与样式无关的文本属于内容，各自占一个文件（游戏名与版本 → `info.json`，关于页正文 → `about.txt`，剧本 → `story/`，素材 → `gui/` `images/` `audio/`）。判断口径：这段东西改了会不会影响版式？只有影响版式的才进 `theme.json`。反例见 §2.17（`about` 曾写在 `theme.json` 里，2026-09-27 移出）。
- **设置项的存在性、类型与取值范围只写在 `style/settings.js` 的 `SPECS` 一处**；`pages.settings.sections` 只负责显示哪些、什么顺序、什么文案。新增设置项的完整路径：先在 `SPECS` 登记，再在模板 `theme.json` 的 `sections` 里引用。
- **按键与输入相关字段的权威说明在 [输入与按键](输入与按键.md)**；本文件只保留 `input` 的字段表与设置页 `sections` 的字段表，动作清单、绑定语法、轮盘参数不在此重复。
