# 信息配置（info.json 配置手册）

`info.json` 是工程级配置文件，保存游戏的标识信息、存档开关与资源预加载策略。它与 `theme.json` 职责分离：

- `info.json`：游戏身份（`name` / `version`）、存档开关（`autoSave` / `quickSave`）、预加载策略（`preload`）。
- `theme.json`：样式与界面（见 `样式控制.md`）。

构建时编译器把本文件与引擎模板的 `info.json` **深度合并**（缺字段继承默认，`null` 视为显式置空），再把合并结果并入 `theme.info`；运行时各模块从 `window.__THEME__.info` 读取。合并语义见 `编译原理.md`。剧本指令见 `指令.md`；引擎总体设计见 `定义.md`。

## 1. 快速开始

最小可用配置：

```json
{
  "name": "Example Game",
  "version": "1.0.0",
  "autoSave": true,
  "quickSave": true,
  "preload": {
    "boot": "title",
    "runtime": ["page", "predict"],
    "timeout": 12000,
    "onTimeout": "hint",
    "slowSpeedKBps": 250
  }
}
```

要点：

- `name` / `version` 均可省略；省略后对应位置不显示。
- `autoSave` / `quickSave` 默认 `true`，关闭会影响存档界面与首页「继续」按钮。
- `preload` 只写需要改的字段即可：`lookahead` / `chapter` / `stage` / `fastForward` / `fallback` 全部省略时取模板默认值（见 §5.10 的完整形态）。
- 修改 `info.json` 后必须重新构建工程（`aliceadv build <工程目录>`），否则不生效。

## 2. 顶层字段一览

| 字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `name` | string | 否 | 游戏名，用于首页标题与关于页 | — |
| `version` | string | 否 | 游戏版本号，用于首页标题与关于页 | — |
| `autoSave` | boolean | 否 | 是否启用自动存档 | `true` |
| `quickSave` | boolean | 否 | 是否启用快速存档 | `true` |
| `preload` | object | 否 | 资源预加载策略（遮罩等待 + 运行时调度 + 兜底动作） | 见 §5.1 |

表中「—」表示模板 `info.json` 不含该键，省略后使用模板默认值。

## 3. name / version

- `name`：显示在首页标题区（`theme.json` 的 `pages.title.showName` 不为 `false` 时）与关于页标题。
- `version`：显示在首页标题区（`pages.title.showVersion` 不为 `false` 时）与关于页「游戏版本」。

两者均可省略；省略后首页与关于页对应位置留空。

**引擎版本不在此配置。** 运行时界面展示的引擎名称与版本由构建时注入的 `window.__ENGINE__` 提供，取自引擎包的 `ENGINE_NAME` / `ENGINE_VERSION`（定义在 `aliceadv/src/aliceadv/__init__.py`，版本号的唯一来源是 `aliceadv/src/aliceadv/_version.py`），随引擎升级自动变化。工程无需也无法声明引擎版本。改引擎版本见 `编译原理.md` §5.2。

## 4. autoSave / quickSave

这两个布尔值是存档系统的总开关，由 `script.js` 的 `cfgBool("autoSave", true)` / `cfgBool("quickSave", true)` 读取（缺省视为 `true`）。

| 字段 | 默认值 | 关闭（`false`）后的影响 |
|---|---|---|
| `autoSave` | `true` | 自动存档槽从存档 / 读档页消失；首页「继续」按钮置灰且点击无效（按钮是否显示仍由 `theme.json` 的 `buttons` / `customButtons` 决定） |
| `quickSave` | `true` | 快速存档槽从存档页消失；菜单「快存 / 快读」与舞台工具栏对应按钮失效 |

关闭 `autoSave` 时，若 `theme.json` 的 `buttons` / `customButtons` 仍保留了 `continue`，首页会呈现一个置灰、点击无效按钮。建议同步移除 `continue` 以避免该状态。

## 5. preload（资源预加载策略）

`preload` 控制三件事：进入网页与进入舞台时的遮罩等待、游戏运行中的资源预取调度、以及资源确实来不及时的兜底动作。读取与执行由 `style/preload.js` 的 `AliceADVPreload` 模块完成；策略来源为 `window.__THEME__.info.preload`。

各字段背后的机制（时间模型、调度器、五个触发点、兜底分档、资源归属规则）见 `预加载.md`；本节只定义字段与取值。

### 5.1 概述

| 子字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `boot` | string | 否 | 进入网页时强制加载的素材范围；首屏就绪即渐隐启动遮罩（见 5.2） | `"title"` |
| `runtime` | array \| string | 否 | 运行时预加载 hook；`[]` 表示全部关闭（见 5.3） | `["page","predict"]` |
| `lookahead` | object | 否 | 时间轴窗口与每句耗时（见 5.4） | 见 5.4 |
| `chapter` | object | 否 | 章范围与章首遮罩的等待目标（见 5.5） | 见 5.5 |
| `stage` | object | 否 | 进入舞台时的开场加载（见 5.6） | 见 5.6 |
| `fastForward` | object | 否 | 快进期间的语音策略（见 5.7） | 见 5.7 |
| `fallback` | object | 否 | 资源未就绪时的兜底动作（见 5.8） | 见 5.8 |
| `timeout` | number | 否 | 遮罩等待多久后触发 `onTimeout`（ms，取值范围 1000~120000） | `12000` |
| `onTimeout` | string | 否 | 到点后继续等待还是放行（见 5.9） | `"hint"` |
| `slowSpeedKBps` | number | 否 | 判定「网络较慢」的实测速率阈值（KB/s，最小 1） | `250` |

取值归一化由 `getStrategy()` 统一执行：

| 情况 | 处理 |
|---|---|
| 值不在允许集合内（`boot` / `onTimeout` / `chapter.scope` / `chapter.preload` / `fallback` 的动作字段） | 回落该字段的默认值；不做前缀匹配，也不做大小写兼容 |
| 数值超出上下限 | 截断到边界（`timeout:500` → `1000`；`slowSpeedKBps` 只有下限） |
| 数值不是 number，或为 `NaN` / `Infinity` | 回落默认值 |
| 布尔字段传 `false` 之外的任何值（含 `"false"`、`0`） | 视为 `true` |
| `preload` 整个字段缺失 | 全部取默认值 |

运行时可用 `AliceADVPreload.getStrategy()` 读取归一化之后的生效结果，不要凭 `info.json` 原文推断。

### 5.2 preload.boot

| 取值 | 加载范围 | 默认 |
|---|---|---|
| `"none"` | 不强制加载，遮罩立即消失 | 否 |
| `"title"` | 首页素材：`pages.title.background` 与 `customButtons` 的 `image` / `hover` | 是 |
| `"system"` | 首页 + 各启用系统页背景 + 舞台背景；`gallery` / `branches` / `chapters` 对应目录为空视为禁用，跳过其专属素材 | 否 |
| `"title+story"` | 首页 + 全部剧情素材（所有剧本的 `bg` / `show` / `music` / `sound` / `voice` 资源路径 + 角色档案全部立绘 + 角色专属对话框） | 否 |

`boot` 阶段阻塞启动遮罩，直到**首屏**（首页背景与首页按钮图）加载完成；超过 `timeout` 仍未就绪时按 `onTimeout` 处理（见 5.9）。本策略范围内的其余资源随后在后台按序加载（见 5.9.1）。

默认值说明：`"title"` 只等待首页，启动速度快，且避免首页背景「慢慢浮出」，是多数游戏的折中值。`"system"` 与 `"title+story"` 启动更慢，分别适用于担心系统页切换空白、或愿接受较长启动以换取进入游戏后零加载延迟的场景。

### 5.3 preload.runtime

运行时预加载策略，可写成数组或单个字符串；设为 `[]` 表示关闭运行时预加载。数组中的其它键会被丢弃。

| 键 | 行为 |
|---|---|
| `"page"` | 切换页面前，后台预加载目标页背景，不阻塞切换 |
| `"predict"` | 剧情推进时按时间轴窗口向前规划待取资源，按 `slack`（`deadline − 预计下载耗时`）升序入队；会跟随 `goto` / `if` 进入后续段，并把 `decide` 的**各**选项分支都作为并列时间线纳入；同时驱动进入舞台时的开场加载（见 5.6） |

默认 `["page", "predict"]` 可同时获得「页面切换平滑」与「剧情资源就绪」，且不引入可感知副作用。设为 `[]` 时，未预载的资源在实际用到时由 DOM 渲染触发惰性加载，表现为逐条出现的加载延迟。

`"predict"` 是 `enterStage()` 开场加载与运行中调度的共同开关：关闭它，进舞台时不显示遮罩，也不做任何提前规划。

### 5.4 preload.lookahead

时间轴窗口与每句耗时。窗口以**秒**为单位，向前扫描的指令条数由「秒数 ÷ 每句耗时」实时换算，不再是指令条数。

| 子字段 | 类型 | 必填 | 说明 | 默认值 | 取值范围 |
|---|---|---|---|---|---|
| `windowSeconds` | number | 否 | 高保障区长度：预计在这么多秒内用到的资源全力保证 | `30` | 1~3600 |
| `horizonSeconds` | number | 否 | 规划上界：超过这个秒数的资源不排队，留到下次推进重算 | `180` | 1~7200 |
| `maxInstructions` | number | 否 | 单次时间轴遍历的指令条数上限，用于给环与超长段兜底 | `600` | 10~100000 |
| `defaultLineSeconds` | number | 否 | 无实测样本时，一句按多少秒计 | `3` | 0.05~120 |
| `autoLineSeconds` | number | 否 | 自动播放模式下一句的秒数 | `2.6` | 0.05~120 |
| `skipLineSeconds` | number | 否 | 快进模式下一句的秒数 | `0.18` | 0.01~120 |

`horizonSeconds` 小于 `windowSeconds` 时取 `windowSeconds`，不会出现上界低于窗口的组合。

`defaultLineSeconds` 只在玩家还没有产生任何实测样本时生效；有样本后改用实测的每句耗时（正常模式）。`autoLineSeconds` / `skipLineSeconds` 是模式常量，必须与 `script.js` 的定时器周期一致（`autoTimer` 2600ms、`skipTimer` 180ms），改动任一侧都要同步另一侧与模板 `info.json`；该一致性由 `aliceadv/tests/test_preload_order.py` 断言守住。

`skipLineSeconds` 同时决定快进时的前瞻深度：0.18 秒/句意味着 30 秒窗口覆盖约 160 句。

### 5.5 preload.chapter

| 子字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `scope` | string | 否 | `"current"`：遍历不跨越章边界；`"all"`：允许规划到后续章的开头 | `"current"` |
| `preload` | string | 否 | 章首遮罩的等待目标：`"adaptive"` 只等壳图 + 首帧 + 前奏；`"complete"` 扩为章内全部可达资源 | `"adaptive"` |

章是预加载的**搜索上界**：默认只规划当前章，不把下一章的素材提前拉下来。章与章之间的资源缺口由**章首加载页**承担（进入新章必然经过 `enterStage()`，见 5.6），不由章末预取承担。

`preload:"complete"` 面向「不愿被任何加载打断、也不会中途缺素材」的作者：遮罩等到章内全部可达资源就绪才揭开。它不引入第二套等待策略，`timeout` / `onTimeout` 仍是那两个旋钮；配合默认的 `onTimeout:"hint"` 表示「慢网下继续等并给出说明」。

一个剧本文件就是一章时，`scope` 用默认值即可。若在同一文件内用嵌套 `chapters` 划分多章，章与章之间没有独立加载页，必须把 `scope` 设为 `"all"`。

### 5.6 preload.stage

进入舞台（「开始游戏」/「继续」/ 读档 / 快速读档）时的开场加载。

| 子字段 | 类型 | 必填 | 说明 | 默认值 | 取值范围 |
|---|---|---|---|---|---|
| `preludeSeconds` | number | 否 | 前奏窗口：按剧情秒选取「接下来这么久会用到的图片」 | `60` | 0~3600 |
| `preludeImagesOnly` | boolean | 否 | 前奏是否只统计图片（音频不参与，避免大音频挤占等待预算） | `true` | — |
| `preludeBudgetSeconds` | number | 否 | 前奏最多花掉的**下载时间**（按实测速率折算），超支即切断 | `8` | 0~600 |

揭幕前要等的资源分三组，区别是「等不等得起」：

| 组 | 内容 | 等待方式 |
|---|---|---|
| ① 外壳图 + 首帧关键集 | `theme.json` 声明的外壳图、`deadline <= 0` 的图片、第一位说话 / 登场角色的专属对话框 | 无条件等满 |
| ② 前奏 | `preludeSeconds` 剧情秒内要用的图片，以及该窗口内其它角色的对话框 | 按 `preludeBudgetSeconds` 截断 |
| ③ 其余 | 规划内剩下的资源 | 不等，揭幕后后台补齐 |

`preludeSeconds` 与 `preludeBudgetSeconds` 回答的是两个不同的问题：前者问「接下来这么久的剧情要用到什么」，只能由剧本给出；后者问「进章前最多让玩家等多久」，只能由链路给出。两个都要设，缺一个就会失衡——只按剧情秒选而不设预算，字节数没有上界，慢网下章首遮罩可能等上分钟；只按预算选而不看剧情秒，又无从判断哪些资源值得先花掉预算。

预算按规划输出顺序（已是 `slack` 升序）逐项累加，超支即切断，不跳过超支项去捡后面的小文件：顺序即优先级，跳着取会破坏这个性质。`preludeBudgetSeconds: 0` 表示前奏组完全不等待。

前奏窗口内可能包含十个以上角色，他们的专属对话框同样受该预算约束，否则十几张图足以吃光整个预算。

若视野内没有任何可预载资源，不显示遮罩，避免无意义闪一下。

### 5.7 preload.fastForward

| 子字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `skipVoice` | boolean | 否 | 快进期间不预载语音、也不播放语音 | `true` |

语音在快进时通常不会被听完，把它移出队列可以为图片让出带宽。这只影响快进期间：`setSkip(false)` 之后恢复正常，已跳过的语音在下一次规划中重新纳入。

判据只有一处（`preload.js` 的 `skipVoiceActive()`），预载侧与播放侧共用，避免出现「不加载但照样播」或「加载了却不播」的不一致。

语音占本项目资源体积的 61%，却不会造成画面缺失。带宽紧张时先省语音是这套机制的默认取向；`false` 适用于语音本身很短、或作者要求快进也保留人声的场景。

### 5.8 preload.fallback

资源在指令执行时仍未就绪的处理动作。

| 子字段 | 类型 | 必填 | 说明 | 默认值 |
|---|---|---|---|---|
| `default` | string | 否 | 未单独指定类型的兜底动作 | `"degrade"` |
| `image` | string | 否 | 图片（`bg` / 立绘 / 整屏图 / 对话框）的兜底动作 | `"block"` |
| `audio` | string | 否 | 音频（`music` / `sound` / `voice`）的兜底动作 | `"degrade"` |
| `allowSkipWait` | boolean | 否 | 兜底遮罩上是否显示「不等了」按钮 | `true` |
| `maskDelayMs` | number | 否 | 等待多久还没就绪才亮出遮罩（ms，0~5000，0 = 立刻） | `150` |

动作取值：

| 动作 | 行为 |
|---|---|
| `"block"` | 等待该资源就绪，期间显示 `#wait-mask`（转圈 + 字节加权进度 + 可选的「不等了」） |
| `"degrade"` | 不等。图片保持上一画面或主题兜底背景；音频延迟起播或静音 |
| `"missing"` | 不等，且不做兜底。背景露出 `body` 默认背景色，立绘不显示 |

默认取向的理由：画面缺失是玩家直接看得见的缺陷，且图片体积小（本项目平均 0.79 MB），等待代价低；音频占体积的 61%，等待它收益最低、代价最高。

`"degrade"` 与 `"missing"` 的区别是实现层面的：`"degrade"` 保留 `.stage-bg` 的主题兜底图与 CSS 渐变色（与 `resetStage()` 的复位目标一致），`"missing"` 额外清掉内联兜底，让 `body` 背景色露出来。

`allowSkipWait` 的「不等了」只让当前这一项按 `"degrade"` 处理并立即继续，不做全局模式切换，也不影响后续资源。

`maskDelayMs` 只影响观感，不影响正确性：绝大多数指令要的资源就在缓存里，判定只需几毫秒（实测 0~3 ms），立刻显示遮罩再立刻隐藏就是闪一下。`0` 表示只要有等待就显示。

兜底是**正确性保证**，调度只影响触发频率：无论排序多精确，都无法保证「玩家推进速度 × 资源体积」始终低于链路能力。资源状态为「已失败」时不参与等待——等坏资源等于卡死。

### 5.8.1 block 的判据是「此刻画不画得出来」

`block` 判的不是「引擎预载过这张图没有」，而是「浏览器此刻能不能立刻把它画出来」：引擎会对该资源走一次真实的取用路径（`Image` 的 `load` + `decode`）。

| 情况 | 结果 |
|---|---|
| 命中缓存 | 几毫秒返回，遮罩不出现（小于 `maskDelayMs`），玩家无感 |
| 未命中 | 等到下载 + 解码完成，超过 `maskDelayMs` 即显示遮罩 |

这条判据是必要的：预载只负责「把响应留给浏览器」，之后缓存在不在不由引擎决定——DevTools 勾了「禁用缓存」、缓存条目被淘汰、服务器响应不可缓存（缺 `Last-Modified` / `Cache-Control`）时，绘制都会重新联网。只按「预载过没有」判断，会出现「判据说已就绪、实际半张图、且不显示遮罩」。

副作用是「一图多取」不再存在：同一张图连续被多条指令用到时，每条都会做一次取用校验，但都是缓存命中。

### 5.9 遮罩等待（timeout / onTimeout / slowSpeedKBps）

`boot()` 与 `enterStage()` 的遮罩等待走 `waitForPaint()`，行为由这两个字段决定：

| `onTimeout` | 到 `timeout` 时 | 遮罩何时揭开 |
|---|---|---|
| `"hint"`（默认） | 实测网速，在遮罩上补一行提示文字，**继续等待** | 目标资源真正就绪时 |
| `"release"` | 直接放行，不做任何提示 | 到 `timeout` 即揭开，不考虑资源是否就绪 |

`barrier()` 的等待在 `waitWithBarrier()` 里，它**一律等满**（是否提前结束由 `allowSkipWait` 的「不等了」决定），不受 `onTimeout` 影响；但它补提示的门槛与文案与上表同源：同一个 `timeout`、同一个 `hintForNow()`。因此无论玩家卡在哪一层遮罩上（`#boot-mask` 纯黑进章遮罩 / `#wait-mask` 半透明兜底遮罩），超过 `timeout` 都会看到同一句说明。

`"hint"` 下按实测速率二选一显示文案：

| 条件 | 文案 |
|---|---|
| 无可用样本，或实测速率 < `slowSpeedKBps` | 当前网络较慢，加载可能需要较长时间 |
| 实测速率 ≥ `slowSpeedKBps` | 游戏资源体积较大，加载需要更多时间 |

实测速率取自 Resource Timing 里**已完成**资源的单资源传输速率（`encodedBodySize / (responseEnd - responseStart)`）的最大值，只统计 `transferSize > 0` 且体积 ≥ 8KB 的样本。它反映的是测量时刻的实际传输能力，受并发窗口与 RTT 影响会明显低于链路标称带宽，因此 `slowSpeedKBps` 要按实测值来设。默认 `250` 对应「4G 及以下判为网络较慢、家宽 / WiFi 判为资源体积较大」，标定数据见 `预加载.md` §10.3。

`"release"` 保留旧行为：用一个固定秒数赌资源已经就绪。限速条件下赌输的表现是遮罩揭开时首页背景尚未下载完，玩家看到空白或逐行绘制的画面。

两种模式都不会无限等待：单资源的等待上限 30s（`ASSET_TIMEOUT`，不开放配置）是内在兜底。

### 5.9.1 遮罩元素与加载顺序

两层遮罩的 DOM 写死在 `template/index.html`，CSS 在 `template/style/preload.css`：

| 元素 | 用途 | 形态 |
|---|---|---|
| `#boot-mask` | 进入网页、进入舞台 | 纯黑全屏（`z-index:9999`），不读主题色变量，任意主题下观感一致 |
| `#wait-mask` | 剧情中途资源未就绪（`fallback` 为 `block`） | 半透明（`z-index:9990`），舞台画面仍可见，转圈居中 |

两者加上 `is-hidden` 类后渐隐 0.45s，渐隐结束后 `pointer-events` 置为 `none`，玩家方可交互。模板模式且无法加载 `theme.json`（例如直接用 `file://` 打开模板）时，bootstrap 立即隐藏遮罩并展示使用说明——此时遮罩无实际意义。

浏览器对同一源只允许约 6 条并发连接，超出的请求排队、并**按发起顺序**获得连接。因此预加载器内部按「数组顺序」限并发推进（`pump()`，并发窗口 4），**调用方给出的顺序就是下载优先级**。

运行时规划的排序键依次是 `tier` → `slack` → `size`：`tier` 让「正在用 / 已过期」的资源无条件优先，`slack` 让同样紧迫的里面更来不及的先发，`size` 只用于打破并列。资源**类型不参与排序**，体积只参与 `slack` 的计算。

`boot()` 与 `enterStage()` 的批次排在高优先级队列（`bootQueue`），运行时规划排在低优先级队列（`planQueue`），两者共用同一个并发窗口——这样进章时的一整批资源不会被运行中的规划分走连接。

**角色专属对话框（`characters.json` 的 `profile.textbox`）不参与 `boot`**：数量多、单张体积大（本项目 12 张约 10MB），若排进 `boot` 会把首屏与外壳图挤到队尾，限速下表现为「首页长时间空白、背景逐行扫描」。它们改由 `enterStage` / 运行时规划按视野内「即将说话 / 登场」的角色按需预载。

### 5.11 禁用功能的联动

`boot:"system"` 调用 `collectSystem` 时，会先经 `isPageEnabled` 判断功能是否启用：`gallery` / `branches` / `chapters` 对应的 `story/chapters.json` 目录数组为空视为禁用，跳过其专属素材。其余系统页（`save` / `load` / `settings` / `about`）始终启用。

`runtime` 的 `"page"` 策略走 `collectPageAssets`，不判断 `isPageEnabled`；被禁用的系统页不会被导航到，因此不会发起其背景的预加载请求。

## 6. 速查表

| 场景 | 推荐配置 |
|---|---|
| 普通游戏 | 全部默认值（`boot:"title"` / `runtime:["page","predict"]` / `chapter.preload:"adaptive"` / `fallback.image:"block"`） |
| 极小游戏 / 本地调试 | `boot:"none"`，`runtime:[]` |
| 担心系统页切换闪烁 | `boot:"system"` |
| 剧情总量可控、追求进入游戏后零加载延迟 | `boot:"title+story"`，`runtime:["predict"]`，`chapter.preload:"complete"` |
| 慢网下仍要求全程无缺失、可接受章首长时间加载 | `chapter.preload:"complete"` + 默认 `onTimeout:"hint"`，调大 `timeout` |
| 章首加载页不愿久等 | 调小 `stage.preludeBudgetSeconds`（如 `3`） |
| 大音频跟不上、希望优先保住画面 | 默认 `fallback.image:"block"` + `fallback.audio:"degrade"`，保持 `fastForward.skipVoice:true` |
| 不愿出现任何等待遮罩 | `fallback.image:"missing"`，`fallback.audio:"missing"`，`onTimeout:"release"` |
| 希望只要有等待就立刻显示转圈圈（不介意缓存命中时闪一下） | `fallback.maskDelayMs: 0` |
| 目标玩家网络普遍较慢、希望等待时给出说明 | 默认的 `onTimeout:"hint"` + 按需调低 `slowSpeedKBps`（如 `150`） |
| 目标玩家网络快、资源小，不愿多等 | `onTimeout:"release"`，配合较短的 `timeout`（如 `6000`）与 `stage.preludeBudgetSeconds:0` |
