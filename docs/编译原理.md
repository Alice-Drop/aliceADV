# aliceADV 编译原理

说明 `aliceadv build` 从「工程目录」生成「发行产物」的完整过程。重点是**编译期默认值填充**（deep merge）与产物结构。

## 1. 三个角色：模板、工程、产物

| 角色 | 路径 | 内容 | 谁编辑 |
|---|---|---|---|
| 引擎模板 | `aliceadv/src/aliceadv/template/` | `index.html`、`style/`（引擎运行时）、`theme.json`、`info.json`、`gui/`、`story/`、`audio/`、`images/` | 引擎维护者 |
| 用户工程 | 任意目录，如 `girls_orbit_project/` | 只放内容：`theme.json`、`info.json`、`story/`、`gui/`、`images/`、`audio/`、`fonts/` | 游戏作者 |
| 发行产物 | `<工程>/dist/web/` | 引擎运行时 + 工程内容 + 生效配置，自包含 | 不手动编辑 |

两条结构约定：

- `index.html` 与 `style/` **只存在于模板**，不复制进工程目录。构建时从模板装配到产物。工程根目录若残留这两项，构建会忽略并打印提示。
- 模板目录可被环境变量 `ALICEADV_TEMPLATE` 覆盖，指向另一份模板。自定义模板，或用其他语言实现编译器时，都复用该约定。

## 2. 编译入口

```bash
aliceadv build <工程目录>
```

构建前校验，任一不通过即终止且不产出：

| 校验 | 条件 |
|---|---|
| 工程目录存在 | `<工程目录>` 是目录 |
| 不是模板本身 | 目录内不存在 `.aliceadv_engine` 标记文件 |
| 有主题配置 | 目录内存在 `theme.json` |

产物入口：`<工程目录>/dist/web/index.html`。

## 3. 编译期默认值填充（deep merge）

### 3.1 目的

工程只需声明**与默认值不同**的字段，其余由引擎模板补齐。运行时只读合并后的成品配置，不需要区分「用户写的值」与「默认值」。

填充**只针对配置文件**：`theme.json` 与 `info.json`。剧本、角色档案、章节等不是配置，原样复制（见第 7 节）。

### 3.2 单一来源

`aliceadv/src/aliceadv/template/theme.json` 同时承担两个角色：

1. `aliceadv create` 复制进新工程的工程模板；
2. 构建时补默认值的默认配置。

因此不存在第二份「推荐字段清单」，两者不会不同步。

### 3.3 合并语义

引擎模板为「默认」，工程配置为「用户」，逐字段合并：

| 情况 | 结果 |
|---|---|
| 双方都是对象 | 递归合并 |
| 双方都是数组 | 取用户数组，整体替换，不逐项合并 |
| 基本类型，或双方类型不同 | 取用户值 |
| 默认有该字段、用户未提供 | 保留默认值 |
| 用户显式写 `null` | 视为显式置空，保留 `null`，不回落默认 |
| 用户显式写 `""` | 视为显式清空字符串，保留 `""` |

`builder.py` 的 `_deep_merge()` 是该语义的参考实现。其他语言的实现只需遵循上表，不必与 Python 代码逐行一致。

### 3.4 示例

默认配置：

```json
{
  "button": {
    "idle": "gui/button/idle_background.png",
    "tile": true,
    "height": 64
  },
  "sidebar": ["history", "save", "load", "back"]
}
```

工程配置：

```json
{
  "button": {
    "height": 96
  },
  "sidebar": ["save", "back"]
}
```

合并结果：

```json
{
  "button": {
    "idle": "gui/button/idle_background.png",
    "tile": true,
    "height": 96
  },
  "sidebar": ["save", "back"]
}
```

`button.idle`、`button.tile` 未在工程中声明，保留默认；`button.height` 被覆盖；`sidebar` 是数组，整体替换而非合并。

### 3.5 写入位置

生效配置写入**产物**，不修改工程源文件：

| 产物文件 | 内容 |
|---|---|
| `dist/web/theme.json` | 合并后的 theme |
| `dist/web/info.json` | 合并后的 info |

合并后的 `info` 会并入 `theme.info`。运行时通过 `window.__THEME__.info` 读取，供预加载策略与版本显示使用。

字段缺省与显式置空的取舍：想继承默认外观就不要写该字段；想主动去掉某个默认图片，写 `null` 或 `""`。

## 4. 构建步骤

| # | 动作 | 输出 |
|---|---|---|
| 1 | 读工程 `theme.json` / `info.json`，与模板 deep merge | 生效配置（内存） |
| 2 | 由生效配置生成 CSS 变量与浮层停靠 CSS | 内存 |
| 3 | 收集剧本（`story/*.json`） | 内联数据 |
| 4 | 清空旧产物，保留以 `.` 开头的文件与目录 | — |
| 5 | 从模板复制 `index.html`、`style/` | 引擎运行时 |
| 6 | 复制工程内容到产物，应用忽略规则 | 工程内容 |
| 7 | 用生效配置覆盖产物中的 `theme.json` / `info.json` | 生效配置落盘 |
| 8 | 按 `theme.json` 的字体声明生成 `style/fonts.built.css` | 字体 CSS |
| 9 | 按 CSS 文件深度重写 `url()` 相对路径（幂等） | 修正后的 CSS |
| 10 | 写 `style/theme.built.css` | 构建期 CSS 变量 |
| 11 | 改写 `index.html`：引入上述两份 CSS，内联三份全局数据 | 可 `file://` 直接打开的页面 |

第 6 步的忽略规则：`dist`、`.git`、`.gitignore`、`.workbuddy`、`.DS_Store`、`.idea`、`.vscode`、`.aliceadv_engine`、`__pycache__`、`*.pyc`，以及残留的 `index.html` / `style/`。

### 4.1 第 9 步：CSS 资源路径重写

CSS 的 `url()` 相对 **CSS 文件自身**解析，不是相对 `index.html`。模板统一写工程根相对路径（如 `url("gui/textbox.png")`），构建期按文件深度补 `../`：

| CSS 文件 | 深度 | 实际引用 |
|---|---|---|
| `style/base.css` | 1 | `../gui/...` |
| `style/pages/*.css` | 2 | `../../gui/...` |

重写幂等，重复构建不会叠加前缀。

例外：运行时经 CSS 变量注入的图片路径不参与重写。原因见第 6 节。

### 4.2 第 10 步：构建期 CSS 变量

`theme.built.css` 由 `theme.json` 翻译生成，在页面样式之后引入，因此工程配置能覆盖模板默认样式。文件头带有「请勿手改」说明；改 `theme.json` 后重新构建即可。

### 4.3 第 11 步：内联全局数据

`index.html` 在加载 `style/theme.js` 之前插入三份全局数据，使产物在 `file://` 下直接可用，无需额外请求：

```html
<script>window.__ENGINE__ = {"name":"aliceADV","version":"v1.2.3"};</script>
<script>window.__THEME__ = {...};</script>
<script>window.__SCRIPTS__ = {...};</script>
```

（`version` 的实际取值随引擎版本变化，见第 5 节。）

同时引入两份 CSS：`style/fonts.built.css` 置于 `base.css` 之后，`style/theme.built.css` 置于所有页面样式之后。

## 5. 引擎版本注入与版本管理

### 5.1 注入

引擎版本取自引擎包，不取自工程配置，因此工程既无法也无需自行声明引擎版本：

| 常量 | 位置 | 取值 |
|---|---|---|
| `ENGINE_NAME` | `aliceadv/src/aliceadv/__init__.py` | 固定 `aliceADV` |
| `ENGINE_VERSION` | `aliceadv/src/aliceadv/__init__.py` | `"v" + __version__`，由包版本派生 |

构建时写入产物的 `window.__ENGINE__`（见第 4.3 节），`style/theme.js` 运行时读它拼出展示用标签。

游戏版本来自工程 `info.json` 的 `version`，运行时经 `window.__THEME__.info.version` 读取。两者的显示位置见 `样式控制.md` §2.16。

### 5.2 单一来源

引擎版本号在整个仓库中只书写一次：

| 位置 | 内容 |
|---|---|
| `aliceadv/src/aliceadv/_version.py` | `__version__ = "x.y.z"` — **唯一**书写处 |
| `aliceadv/pyproject.toml` | `[project]` 用 `dynamic = ["version"]`，由 `[tool.setuptools.dynamic]` 的 `attr = "aliceadv._version.__version__"` 取值 → 包版本（pip / PyPI） |
| `aliceadv/src/aliceadv/__init__.py` | `from ._version import __version__`；`ENGINE_VERSION = "v" + __version__` |
| 产物 `index.html` | 构建时注入 `window.__ENGINE__` |
| `aliceadv --version` | 输出 `aliceADV x.y.z (engine vx.y.z)` |

`_version.py` 必须保持「零依赖 + 单条赋值」：setuptools 构建时静态解析这一行取版本，不导入包。一旦其中出现 import 或函数调用，静态解析失效，构建环境未必满足导入条件。

改版本就是改 `_version.py` 里的那一行，仓库其余位置不出现版本号，因此不需要任何工具参与。改完重新构建需要带上新版本的工程即可。

不变量由 `aliceadv/tests/test_version.py` 守住（可直接运行，也可被 pytest 收集）：

```bash
python aliceadv/tests/test_version.py
```

它检查四项：`pyproject.toml` 必须走 `dynamic` 而非写死版本；`__init__.py` 必须由 `__version__` 派生 `ENGINE_VERSION`；仓库其余文件不得再出现当前版本号的字面量；`builder.py` 必须仍在注入 `window.__ENGINE__`。任一退化即失败——这是防止「单一来源悄悄退回成两处」的唯一机制。

## 6. UI 图片与 CSS 变量

引擎自带的界面图片（对话框、边框、按钮、画廊占位图）由 `theme.json` 字段声明（见 `样式控制.md` §2.19），运行时写入 CSS 变量，CSS 侧以 `var(--gui-*)` 引用。由此：

- 编译期不做这类图片的路径重写；
- 变量值必须是**绝对 URL**（运行时基于 `document.baseURI` 解析）。CSS 变量里的 `url()` 由使用该变量的样式表解析，而 `style/` 与 `style/pages/` 深度不同；写相对路径会被解析到错误目录，导致图片 404。

## 7. 不参与默认值合并的内容

以下属于工程内容，构建时原样复制：

| 内容 | 路径 |
|---|---|
| 剧本 | `story/*.json` |
| 图片 | `images/`、`gui/` |
| 音频 | `audio/` |
| 字体文件 | `fonts/` |

模板中的对应文件是**示范内容**（示范剧本、示范角色、示范图）。`aliceadv create` 会把它们复制进新工程，之后由作者替换。

角色档案不在构建期逐字段补默认值。作者从模板复制整份结构后自行修改，避免「多个角色各自继承一套默认值」带来的维护成本。

## 9. 维护约定

- 修改 deep merge 语义、产物结构或注入内容时，必须同步更新本文档。
- 模板与编译器分离：`template/` 不含 Python 代码。移植编译器时复用模板目录与 CLI 语义即可。
- 新增构建步骤时，在第 4 节表格中补一行；涉及新的全局数据注入或路径重写规则时，在第 4.1 至 4.3 节补充说明。
