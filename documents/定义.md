开放avg引擎/aliceADV，其最大的特点是提供足够的开放程度：

引擎完全开源（MIT LICENSE）；
引擎本身使用纯HTML来渲染，比web assembly等要轻一些，而且制作出的游戏直接丢到github page上就能实现发布；
特别适合玩家用来分发demo，或者制作开放版权的同人游戏（宣传的时候当然是要以同人游戏引擎这个去宣传，流量大），因为游戏文件可以完全开放（游戏文件包内部用csv/json和图片的通用格式，非常方便玩家之间互相二创、三创、移植到其他平台等）；引擎比较方便移植到各个平台，这样甚至可以形成一种通用游戏包格式，

## 通过theme.json定义控件样式与位置

theme.json才是用户开发的时候用到的。这个的设计核心就是只暴露少量的接口，用户只能控制几个控件少量的参数，让用户不需要自己写完整的CSS来实现整个AVG游戏。可以选择提供高级模式让用户自己写各个页面的CSS
用里面限定的接口的形式来简化avg游戏开发。通过极大缩限自由度，来提供大量已经开发好的东西，来减少用户的负担。

软件提供了传统AVG游戏中包含的所有页面，
- page_title 是游戏开始页面
- page_save 游戏保存页面
- page_load 游戏加载页面
- page_settings 游戏设置页面
- page_chapters 游戏章节选择
- page_branches 故事线分支跳转，更加上帝视角的跳转，很多游戏通常不提供这个功能，就不去实现这个即可
- page_stage 舞台，即ADV中最重要的角色进行对话和演出的游戏内容页面。
- page_gallery 已解锁立绘欣赏页面。后面可以考虑把音乐欣赏也加入。
- page_about

当然，游戏不一定全部页面都要用上，可以不定义某些页面。

而且像renpy一样，有几套默认的布局，方便快速开始。

### 按钮
开始界面的按钮已经定义好，分别是开始游戏按钮、继续游戏按钮、load按钮、设置、关于、Gallery、Chapter、剧情分支预览，分别用来跳转到各个页面。还有个退出游戏按钮。


按钮可以填写文字，也可以直接通过设置图片来做。如果是图片，按钮有 idle 和 hover 两个状态，但也可以不设置 hover 的图片。

#### 自定义热区按钮（图片按钮）
在 `theme.json.pages.title` 里用 `customButtons` 数组完全替代默认按钮列表。每个按钮通过 `action` 映射到已有功能，并通过 `left/top/width/height` 在主菜单背景图上定位热区：

```json
{
  "pages": {
    "title": {
      "layout": "custom",
      "background": "gui/main_menu.png",
      "showName": false,
      "showVersion": false,
      "customButtons": [
        { "action": "start",    "left": 0.02, "top": 0.70, "width": 0.22, "height": 0.10 },
        { "action": "load",     "left": 0.02, "top": 0.83, "width": 0.20, "height": 0.10 },
        { "action": "help",     "left": 0.78, "top": 0.04, "width": 0.12, "height": 0.08 },
        { "action": "quit",     "left": 0.82, "top": 0.14, "width": 0.10, "height": 0.07 },
        { "action": "about",    "left": 0.80, "top": 0.30, "width": 0.12, "height": 0.08 },
        { "action": "settings", "left": 0.76, "top": 0.72, "width": 0.20, "height": 0.10 }
      ]
    }
  }
}
```

- `action` 可选：`start`、`load`、`settings`、`chapters`、`gallery`、`branches`、`about`、`help`（映射到 about）、`quit`。
- 若提供 `image` 与 `hover`，则渲染为图片按钮；否则渲染为透明热区（适合主菜单背景上已有手写文字的情况）。
- `left/top/width/height` 是相对值（0~1，相对于 1920×1080 设计画面），构建后转为百分比。
- 配置 `customButtons` 后，默认的 `buttons` 列表不再渲染。


### 通用项

#### 字体
所有显示文字的地方均可以自定义字体、文字大小、文字颜色。

引擎通过 `theme.json` 的 `fonts` 字段配置字体，分为四个角色：

- `text`：对话/旁白正文
- `interface`：界面文字（菜单、按钮、提示等）
- `title`：标题类文字（主菜单标题、页面标题）
- `system`：系统文字（跳过提示、错误信息等），一般直接用系统字体栈

每个角色有两种写法：

1. **字符串（系统/Web 字体栈）**：直接写 CSS `font-family` 值，例如
   `"PingFang SC", "Microsoft YaHei", sans-serif`。适合使用操作系统已安装字体。
2. **对象（自定义字体文件）**：声明一个 `family` 名称 + 字体文件 `src`（工程根相对路径），
   构建时会自动生成 `@font-face` 并装配字体文件，例如：

   ```json
   "fonts": {
     "text":      { "family": "SourceHanSansLite", "src": "fonts/SourceHanSansLite.ttf",
                    "fallbacks": "\"PingFang SC\", \"Microsoft YaHei\", sans-serif" },
     "interface": { "family": "SourceHanSansLite", "src": "fonts/SourceHanSansLite.ttf" },
     "title":     { "family": "SourceHanSansLite", "src": "fonts/SourceHanSansLite.ttf" },
     "system": "system-ui, -apple-system, \"PingFang SC\", \"Microsoft YaHei\", sans-serif"
   }
   ```

**约定**：
- 自定义字体文件放在工程根的 `fonts/` 目录下（如 `fonts/SourceHanSansLite.ttf`），
  构建时自动复制到 `dist/web/fonts/` 并生成 `dist/web/style/fonts.built.css` 的 `@font-face` 声明。
- `src` 一律写工程根相对路径（`fonts/xxx.ttf`），由编译器在编译期按 CSS 文件深度自动重写 `url()`，
  用户无需手写 `../` 前缀（且该重写是幂等的）。
- `fallbacks` 可选，填一个 CSS `font-family` 兜底栈；当自定义字体加载失败时降级到系统字体，避免无字可显。
- 同一字体被多个角色引用时，`@font-face` 自动去重，只声明一次。
- 默认（core 模板）字体栈为无衬线中文安全栈，不依赖任何外部字体文件，开箱即用。

### 按钮
所有按钮都可以设置width、height。这个是相对于screen字段里设置的屏幕尺寸来的，实际运行的时候会转换为百分比，例如屏幕设置的是1920x1080, 而某个按钮设置为widht: 192，那么实际输出网页的时候会转换为width: 10%（相对于主画面div），来在游戏主画面div随浏览器视口大小变化而变化。

对话选项提供几种：默认的按钮图片、默认被hover的图片、之前已经点击过的选项按钮（是否指示按钮已经点过是可以配置的）、已经点过的按钮被hover的图片、某些特殊选项可以使用特殊的图片。




### screen
用来定义应用的基础显示数据。

其中最重要的是定义游戏窗口大小。游戏窗口是一个限定高宽比的div，会随用户窗口变化而变大变小，但是保持高宽比，多出的地方填充为定义的颜色。

## 通过设置图片来控制样式
和renpy一样，可以直接修改图片来修改。

### 图片资源的引用方式（重要）
- **JSON / JS 里**（theme.json、story 剧本、脚本内联样式）：统一写**相对工程根目录**的路径，如 `gui/textbox.png`、`images/bg/roof.png`。
- **CSS 里**：`url()` 是相对 **CSS 文件自身**解析的，但模板统一按工程根相对路径书写（`url("gui/textbox.png")`），
  由编译器 `core/cssutil.py` 在构建期按文件深度自动补 `../` 前缀（`style/base.css` → `../gui/`；`style/pages/*.css` → `../../gui/`）。
  该重写幂等，且 `create.py` / `sync_engine.py` / `build.py` 三处共用，重复执行不会累积前缀。
  **因此模板里不要手写 `../../`，照常写 `gui/...` 即可**，新增 CSS 放到任意深度都能自动适配。

## 剧本定义
然后剧情（包括动作和跳转、判定节点的记录等）用csv或json，图片资源直接用图片 因为我们这个主要是面向普通人的，易用性和简单快上手是最重要的，这不仅是在到时候做的编辑器层面要好上手，更加重要的是在引擎设计上就不应该有那么多复杂的概念，比如说AVG游戏常见的好感度系统、根据好感度进行判定自动跳转分支的设计，那么我们应该把一段剧情称为“段”，而分支判定的节点称为“判定”，这样最符合直觉的命名方式。同样地，多数同人游戏/自己做表达自我的游戏开发者只希望做普通的galgame类似的效果，而且ADV用到webGL的可能几乎不存在，我们应该舍弃这类设计。我们这个引擎应当注重快速开发出AVG来，通过填表一般甚至以后拖动节点即可的体验即可完成相关设计，这样才是革命性的创新，就像为什么那么多小游戏开发者用renpy以一样，

## 舞台

### 剧本指令集（API）

剧情按「**段（segments）**」组织；段内是**指令数组**，遇到阻塞指令（`say`/`narrate`/`title`/`decide`/`wait`/`end`）暂停等待玩家点击，非阻塞指令（`bg`/`music`/`sound`/`stop`/`show`/`hide`/`sprite`/`rename`/`goto`/`nvlclear`）立即继续。完整字段见 `core/documents/剧本格式说明.md`。

| cmd | 关键字段 | 阻塞 | 说明 |
|-----|----------|------|------|
| `bg` | `src`, `transition?` | 否 | 切换背景（`images/bg/`）。 |
| `music` | `src?`, `stop?`, `volume?`, `fade?` | 否 | 音乐（循环通道）。 |
| `sound` | `src`, `volume?` | 否 | 音效（一次性通道，与音乐独立）。 |
| `stop` | `what`(`music`/`sound`/`all`) | 否 | 停止音频。 |
| `show` | `char?`, `sprite?`, `src?`, `at?`, `transition?`, `anim?` | 否 | 立绘/图片出现。`char`+`sprite` 查档案；`src` 直接显示图片（生物/道具）。`at`: left/center/right。 |
| `hide` | `char?`/`src?`, `transition?` | 否 | 立绘/图片消失（与 show 同匹配键）。 |
| `sprite` | `char`, `sprite`, `anim?` | 否 | 切换表情（不改站位）。 |
| `say` | `char`, `text`, `sprite?`, `as?` | 是 | 角色说话，自动套用 `color`(名字色) 与 `textbox`(专属对话框)。 |
| `narrate` | `text`, `mode?`(`nvl`) | 是 | 旁白；`mode:"nvl"` 走整屏累积模式。 |
| `nvlclear` | — | 否 | 清空 NVL 整屏（对应 Ren'Py `nvl clear`）。 |
| `rename` | `char`, `to` | 否 | 改名（`？？？`→真名）。 |
| `decide` | `options:[{text,goto}]` | 是 | 选项分支。 |
| `goto` | `segment` | 否 | 跳段。 |
| `wait` | `seconds?`/`ms?` | 是 | 演出等待，可点击跳过。 |
| `title` | `text` | 是 | 章节标题卡。 |
| `end` | `action?` | 是 | 结束（回首页/章节）。 |

**本次引擎升级新增能力**（原引擎缺口）：
- **NVL 整屏旁白**：`narrate{mode:"nvl"}` 逐行累积覆盖整屏、可滚动；`nvlclear` 清空。对应 Ren'Py `narrator_nvl` + `nvl clear`。
- **双音频通道**：`music`（循环 BGM）与 `sound`（一次性 SFX）分离，`stop` 可分别/全部停止。
- **直接显示图片（`src`）**：`show`/`hide` 支持不经过角色档案的图片（demo 的生物、道具）。
- **可跳过等待**：`wait{seconds}`（对应 Ren'Py `pause N`），等待中点击跳过。
- **立绘站位与转场**：`show` 的 `at`(left/center/right) 与 `transition`/`anim`(fade/bounce/shake)。
- **角色专属样式**：`characters.json` 的 `color`（名字颜色）与 `textbox`（专属对话框图片）由 `say` 自动套用。

> 资源目录与 Ren'Py 兼容：`gui/`（文本框/按钮/面板/叠加层）、`images/bg/`（背景）、`images/char/<id>/`（立绘）、`audio/`（音频）。从 Ren'Py Web 构建迁移可用 `core/tools/rpy2adv.py`。
